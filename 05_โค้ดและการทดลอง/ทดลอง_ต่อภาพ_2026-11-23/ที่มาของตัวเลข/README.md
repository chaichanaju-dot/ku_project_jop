## ข้อควรระวังตอนอ้างตัวเลข

1. **มีตัวเลขสองชุดที่ต่างกันเล็กน้อย และทั้งสองถูกตามอินพุตของตัวเอง:** ชุดแรก (e1–e11) คำนวณบน **สำเนาย่อ 1600 px ที่บีบอัด JPEG ซ้ำ (q=92)**, ชุดสุดท้าย (`final_numbers*.py`) คำนวณบน **ไฟล์ต้นฉบับ** เช่น คู่หลอก 0312–0313 = 33 จุด / 0.73 บนสำเนา แต่ 32 จุด / 0.71 บนต้นฉบับ · จำนวนคู่ที่ใช้ 84–87 · **ในเล่มให้อ้างชุดต้นฉบับ** พร้อมบอกวิธี
2. **เกณฑ์ตัวเลขในโค้ดไม่ได้มาจากเปเปอร์** — 8 / 30 จุด · ย่อขยาย 1/3–3 เท่า · หมุน 30° · กระจาย 5% · ขัดกัน 15% · GPS 40% และช่วง 0.4–2.5 · รอบบิน 300 วิ ผู้จัดทำตั้งเองจากภาพชุดนี้ชุดเดียว (`ต่อภาพ_แกน.py` บรรทัด 36–48, 157–158, 186–190, 295) · ratio test 0.75 กับ RANSAC 3 px (บรรทัด 129, 142) เป็นค่าที่นิยมใช้ทั่วไป ไม่มีบันทึกว่าเคยปรับ · ที่มาจากเปเปอร์/OpenCV จริงๆ มีแค่สูตรความมั่นใจ `inliers / (8 + 0.3 × matches)` (Brown & Lowe 2007 §3.2 · OpenCV `matchers.cpp`)
3. เวลาคำนวณวัดบน Intel Core Ultra 9 275HX (24 เธรด · ใช้ 8 เธรด) RAM 31.4 GB Windows 11 · Python 3.13.14 · OpenCV 4.10.0 · NumPy 2.3.5 · Pillow 12.2.0 · NetworkX 3.6.1 · PyMuPDF 1.28.0 · Playwright 1.65.2 · Edge 158.0.4370.33 — เครื่องอื่นต่างได้
4. สคริปต์ผูก path ของเครื่องนี้ และอ่านไฟล์ผลกลาง (`meta_raw.json` `meta.json` `e1.json` `e2.json` และโฟลเดอร์ `small/`) ที่ไม่ได้เก็บไว้ (สร้างซ้ำได้ตามลำดับเวลาในตาราง) — สคริปต์เหล่านี้เป็น **หลักฐานว่าตัวเลขมาจากไหน** ไม่ใช่โปรแกรมที่ออกแบบให้รันเป็นชุด
