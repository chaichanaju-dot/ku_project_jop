**ผลการประชุม แยกตามเรื่อง:**
1. **เลเซอร์/ผิวเอียง (3.6.4)** [น.4–6] — ทีมเห็นว่าระยะเอียงน่าจะเป็นปัญหาจริง (ผิวเอียงทำให้จุดเลเซอร์เป็นรูปคางหมูแทนสี่เหลี่ยม) แนวทางที่เสนอ: ล็อกมุมกล้องไว้ (ยกตัวอย่าง 35°) แล้วใส่ค่าปรับแก้ตามองศา ปรับเฉพาะระยะที่ได้รับผล ระยะแนวนอนไม่กระทบ · อาจารย์ถามว่าต้องทดสอบทุกระยะ/มุมหรือไม่ → ต้องลองกับเครื่องจริง
   - ⚠ เลข "คูณประมาณ 1.5 ที่ 35°" ผู้พูดบอก "ถ้าจำไม่ผิด" และไม่ตรงกับ 1/cos 35° ≈ 1.22 ตามที่ไดอารี่ 10 พ.ย. คำนวณไว้ (วัดเล็กไป cosθ) ยังไม่ควรใช้เลข 1.5
2. **รอยร้าว PC / กล้องเทเล** [น.6] — ยังแทบไม่ได้หาข้อมูลว่าเทเลมีผลอย่างไร ต้องลองกับโดรนจริง ตัวโดรนอยู่กับรุ่นพี่ที่ไปค่ายสำรวจ คาดว่ากลับปลายสัปดาห์นี้หรือสัปดาห์หน้า (น.6 พูดอย่างหนึ่ง น.40 พูดอีกอย่าง)
3. **การแบ่งชุดข้อมูลเก่า/ใหม่** [น.6–8] — ทีมเคยเข้าใจว่าชุดเก่าฝึก 100% ชุดใหม่แบ่งสองส่วน (ฝึก/ทดสอบ) แล้วเข้าใจใหม่ว่าชุดใหม่ทดสอบ 100% · อาจารย์: ภาพชุดใหม่จะเก็บจากหน้างานจริง · นัทกับมะขามเสนอเอาชุดใหม่เข้าฝึกบางส่วน (เช่นภาพบินนำร่องก่อนบินจริง) เพราะระยะบินต่างจากชุดเก่า กลัวโมเดลฟิตที่ระยะเดิม สัดส่วนยังไม่กำหนด (มะขามเสนอราว 50% ถ้าชุดใหม่ราว 100 ภาพ มากกว่านั้นถ้าเป็นพันภาพ รอดูจำนวนจริง) · อาจารย์: ปรับเป็นแบบที่ทีมตั้งใจไว้ก็ได้
4. **ช่วงคะแนนสถานะ (ตาราง 2.7)** [น.8–9, 33] — นัทไม่อยากปรับค่า C อยากปรับช่วงคะแนน (เพราะเป็นการตัดสินว่าควรซ่อมไหม ยืดหยุ่นกว่า) เสนอให้ระดับที่ต่ำกว่าแทรกได้ไม่กี่เปอร์เซ็นต์ก่อนลดสถานะ (ตัวอย่างที่พูด 95/5 ผู้พูดบอกยังไม่แน่ใจเลขที่เหมาะสม) · ผูกกับสูตร: ถ้าสูตรเปลี่ยนอาจไม่ต้องปรับ → **ไม่ได้เลือกข้อเสนอ ก หรือ ข ในที่ประชุม**
5. **ภาพซ้อนทับ กับการนับความเสียหายซ้ำ** [น.9–23]
   - มะขาม: ถ้าถ่ายแบบไม่ซ้อนทับ อาจมีช่องว่างที่มองไม่เห็น ถ้าซ้อนทับต้องต่อภาพ ซึ่งทำให้ไม่อัตโนมัติ (ต้องมีคนจัดว่าภาพไหนเป็นชิ้นส่วนไหน GPS แยกคานไม่ได้เพราะคานยาว ส่วนเสาอยู่จุดเดียว ต่างแค่ระดับความสูง)
   - อาจารย์: ในทางปฏิบัติต้องถ่ายซ้อนทับ ไม่งั้นบางส่วนหลุดและขึ้นโมเดลสามมิติไม่ได้ จึงต้องจัดการเรื่องนับซ้ำ
   - อาจารย์ชี้ว่าถ้าตัวหาร (พื้นที่) โตขึ้นแต่ความเสียหายเท่าเดิม สัดส่วนความเสียหายจะต่ำลง = ประเมินต่ำ ไม่ปลอดภัย ส่วนนัทเข้าใจว่าปลอดภัยขึ้น → **ไม่ได้ข้อสรุปว่าซ้อนทับเอนไปทางไหน**
   - นัทอธิบายสูตร: ค่า C = คะแนนตามระดับ ดัชนีชิ้นส่วน = ผลรวมของ (C × สัดส่วนพื้นที่ของแต่ละระดับในชิ้นส่วน) โดยพื้นที่ไม่เสียหายนับเป็นระดับ 5 · อาจารย์: ค่า Q_E (ปริมาณ/น้ำหนักชิ้นส่วน ไม่ใช่ปริมาณความเสียหาย) ไม่ได้รับผลจากการซ้อนทับ ผลกระทบอยู่ที่สัดส่วนพื้นที่ต่อระดับ · ถ้าชิ้นส่วนเดียวมีหลายภาพ ต้องรวมเป็นก้อนเดียวก่อนคิด (ต่อภาพ หรือให้โปรแกรมรวม)
6. **สองทางที่อาจารย์เสนอ** [น.23–24, 31–32] — ทางที่ 1: คงสูตรที่ใช้ปริมาณความเสียหาย ต้องทำเรื่องรวม/ต่อภาพให้อัตโนมัติที่สุด (มะขามเสนอใช้ Gemini API ที่ใช้ได้ฟรีช่วยคุมการต่อภาพ อาจารย์สงสัยว่าตัวฟรีฉลาดพอไหม มะขามบอกยังไม่เคยลองถึงขั้นนี้ ต้องหาข้อมูลเพิ่ม) · ทางที่ 2: ปรับสูตรเฉพาะระดับที่ 2 (คัดกรอง) ไม่ใช้ปริมาณความเสียหาย ใช้ "ระดับความเสียหายที่แย่ที่สุดรายชิ้นส่วน" แบบ BMMS คูณค่าถ่วงชิ้นส่วนแล้วรวมเป็นสภาพรวมสะพาน (ตัวอย่างอาจารย์: ได้ราว 90 ยังปลอดภัย เหลือราว 60 เริ่มไม่ดี ก็ส่งสะพานนั้นไปขึ้นโมเดลสามมิติของรุ่นพี่ ซึ่งคุมการซ้อนภาพได้) ทางนี้ลดขอบเขตงานประมวลผลภาพ
   - อาจารย์: เป้าหมายระดับ 2 คือคัดกรองให้ราคาสำรวจถูกพอจะทำจริงและคนทั่วไปทำได้ (แลกความแม่นกับความง่าย) ลองทางแรกก่อนก็ได้ ถ้าไม่ได้ค่อยกลับมาปรับสูตร
   - สรุปปลายเรื่อง: 2 ประเด็นพ่วงกัน (ก) จะใช้สูตรนี้หรือไม่ ต้องเช็กสูตรในเล่มอีกรอบ ขึ้นกับว่ารวมภาพได้แค่ไหน (ข) ดึงความเสียหายจากภาพทีละภาพโดยไม่สนซ้อนทับ (สูตรอาจไม่ต้องใช้พื้นที่) หรือรวมภาพเป็นหนึ่งชิ้นส่วนก่อน (ตอนนี้ไม่จำเป็นต้องอัตโนมัติ ค่อยพัฒนาภายหลังได้)
7. **ที่มาของสูตร / AASHTO** [น.24–31] — อาจารย์เปิดคู่มือ AASHTO (ส่วนระบบจัดการสะพาน) ซึ่งเป็นต้นทางของสูตรดัชนีที่ทีมค้นเจอ: ในนั้นตัวแปรคือ "เปอร์เซ็นต์ของชิ้นส่วนที่อยู่ในสถานะสภาพนั้น" ไม่ใช่เปอร์เซ็นต์ความเสียหาย มี 4 สถานะ (ของทีมมี 5) และไม่มีตัวอย่างคำนวณ → อาจารย์ไม่มั่นใจว่านิยามปริมาณในสูตรของทีมตรงกับ AASHTO ทีมบอกดึงมาจากเอกสาร T-BHI (สมการ 4.2.1 หน้า 57 ของเกณฑ์ประเมิน BHI สังเคราะห์) อาจารย์ส่งไฟล์ 2 ชิ้นทาง Google Chat (มาตรฐาน AASHTO กับเปเปอร์ที่สอง) ให้ทีมอ่านเทียบ → **ติดไว้ ยังไม่เคลียร์**
   - ที่มาของขอบเขตปริมาณความเสียหายในเอกสารถูกอ้างว่าอิงเปเปอร์ปี 2009 ชื่อผู้เขียนถอดเสียงเป็น "เพอริจาโน" (น.25)
8. **เปเปอร์ที่สอง (สูตรอย่างง่าย)** [น.30, 34–37] — ชื่อถอดเสียงหลายแบบ (เพย์เลกิโน / เฮเลคิโน่ / เพลงโน่ / เพอริจาโน) น่าจะเป็นชื่อเดียวกัน = Pellegrino ที่เล่มอ้างในตาราง 2.8 (มีค่าถ่วงชิ้นส่วน W) และอาจารย์ว่าเป็นของอิตาลี แต่ยังไม่ยืนยันกับตัวไฟล์ · นัทอ่านแล้วสรุป: ใช้ระดับแย่สุดรายชิ้นส่วน (แบบ BMMS) ไม่มีตัวหาร ไม่ใช้ปริมาณพื้นที่ ไม่กระทบจากภาพซ้อน มีกลไกรองรับชิ้นส่วนที่ไม่ได้ตรวจ (ชื่อตัวแปรไม่ชัด) ผลเป็นระดับความเร่งด่วนในการเข้าจัดการ ไม่ใช่คะแนน และมีปัจจัยอื่นด้วย (ชั้นถนน ปริมาณจราจร ความสำคัญของเครือข่าย อายุโครงสร้าง) · ข้อดี: ง่าย เหมาะคัดกรอง · ข้อเสีย: คานที่มีรอยเดียวกับคานที่เสียหายทั้งตัวได้ระดับเท่ากัน · อาจารย์: ตอบโจทย์ระดับ 2 ของทีมเกือบทั้งหมด แต่ถ้าจัดการปริมาณความเสียหายได้ก็กลับไปใช้ AASHTO · ต้องไปเช็กสูตร AASHTO ก่อน · นัทจะให้ AI อ่านเอกสารแบบไม่ตีความ และอาจารย์แนะให้ค้นตัวอย่างการคำนวณ BHI ออนไลน์
9. **ประเมินผลโดยวิศวกรภายนอก** [น.33] — อาจารย์เห็นว่าควรแบ่งประเมิน 3 ส่วนเหมือนตอนพรีเซนต์: ระดับที่ใช้กับความเสียหายถูกไหม · การแบ่งส่วน (segmentation) ถูกไหม · ระบุชิ้นส่วนถูกไหม ส่วนการใช้สูตรไม่น่ากังวล
10. **ฝึกโมเดล/เครื่องแล็บ** [น.37–40] — รุ่นพี่วินฝึกตัวตรวจจับความเสียหายบน Colab แล้วย้ายมาฝึกบนเครื่องแล็บ (ใช้ตระกูลทรานส์ฟอร์เมอร์ อาจารย์ว่าจะใช้ "เควิน" (น่าจะ Qwen) หรือทรานส์ฟอร์เมอร์อื่นก็ได้) อาจารย์จะแชร์ repo งานของวินให้ทีมช่วงปลายสัปดาห์ (ถอดเสียงสองที่ไม่ตรงกัน: กลางสัปดาห์หน้า / ปลายสัปดาห์) มีอัปเดตต่อเนื่อง · เข้าเครื่องแล็บทาง SSH (อาจารย์ตั้งบัญชีให้ ทีมใช้ Claude Code คุมได้ ถอดเสียงเป็น "คอร์ส") ทีมเคยใช้ SSH กับเครื่องเช่า ข้อมูลทีมอยู่บน GitHub (repo โครงงาน) อาจารย์จะส่งคู่มือตั้งค่าทาง Google Chat
11. **นัดหมาย** [น.40–41] — นัดคุยต่อประมาณ 24 พ.ย. ช่วงเย็น เวลาเดิม (ทีมต้องดูตารางเรียนใหม่ก่อน ถึงเวลานั้นเปิดเทอมแล้ว จะออนไซต์ก็ได้) · พรีเซนต์ปิดโครงงาน: อาจารย์เดาว่าราว 30 มี.ค. 2570 (วันแรกหลังสอบถึง 29 มี.ค.) · อาจารย์ให้ทีมพักช่วงปิดเทอมเต็มที่
