## แหล่งภาพ 2 ทาง แยกตามความ private (และวิธี label ต่างกันด้วย)

| แหล่ง | เครื่องมือ label | วิธี label | เหตุผล |
|---|---|---|---|
| ภาพรอบบินโดรน (`Bridge/` — private) | **LabelMe** (ออฟไลน์ ไม่อัปโหลดไหน) | **label โครงสร้าง+ความเสียหายปนกันในภาพเดียวได้** (ดูเหตุผลหัวข้อ "แยกเป็น 2 ชุด") | ไม่อยากเผยแพร่ตำแหน่ง/สภาพสะพานจริง |
| ภาพอื่นที่ไม่ private (เช่น จาก Roboflow Universe) | **Roboflow** | **แยกเป็น 2 โปรเจกต์เด็ดขาด** — ความเสียหาย = โปรเจกต์ Object Detection ล้วนๆ, โครงสร้าง = โปรเจกต์ Instance Segmentation ล้วนๆ (ภาพที่มีทั้งคู่ ต้องเอาไป label ทั้ง 2 โปรเจกต์แยกกัน) | ให้ export เป็น YOLO ตรงๆ ได้เลย ไม่ต้องผ่าน COCO/สคริปต์แปลงเอง (ตัดสินใจเปลี่ยนจากเดิม 2026-09-25 — ดู `work_diary.md`) |

## ติดตั้ง LabelMe

```
pip install labelme
pip install labelme2yolo
```
เปิดใช้งาน (แนะนำให้ตั้ง class list ไว้ก่อน กันพิมพ์ชื่อ class ไม่ตรงกัน):
```
labelme --labels classes.txt --validate-label exact
```
`classes.txt` = ไฟล์ text ธรรมดา ใส่ชื่อ class ทั้งหมด (โครงสร้าง+ความเสียหาย) บรรทัดละ 1 ชื่อ

## หลักการ Label

**สำหรับ LabelMe (ภาพโดรนจริง `Bridge/`):**
1. **Label ตามที่เห็นจริงในแต่ละภาพ ไม่ต้องคัดแยกภาพก่อน** — ภาพมีแค่โครงสร้างก็วาดแค่โครงสร้าง มีแค่ความเสียหายก็วาดแค่ความเสียหาย มีทั้งคู่ก็วาดทั้งคู่ในภาพเดียวกัน (LabelMe รวมทุก class ไว้ใน JSON ไฟล์เดียวอยู่แล้ว ไม่มีข้อจำกัดเรื่อง project type แบบ Roboflow)
2. **วาดเป็น polygon (segmentation) ไว้ก่อนเสมอสำหรับชิ้นส่วนโครงสร้าง** เพราะ polygon แปลงลงเป็น box ได้ทีหลัง แต่ทำย้อนกลับไม่ได้
3. **สำหรับความเสียหาย (จะไปเทรน RT-DETR ซึ่งอ่านได้แค่ box) — วาด Box ตรงๆ ได้เลย ไม่ต้องเสียเวลาไล่จุด polygon**
   - กรอบต้องครอบความเสียหายให้ครบทั้งชิ้น ห้ามตัดขาด
   - 1 กรอบ = 1 ความเสียหาย ห้ามลากกรอบใหญ่ครอบหลายจุดพร้อมกัน
   - กรอบเฉียง/มีมุมว่างจากรูปทรงไม่สม่ำเสมอ **ไม่ต้องกังวล** — ตอนใช้งานจริง SAM จะหารูปทรงจริงจากในกรอบให้เอง ไม่นับพื้นที่ว่างในกรอบ

**สำหรับ Roboflow (ภาพที่ไม่ private):**
1. **แยกโปรเจกต์เด็ดขาดตามชนิดโมเดล** (ไม่ผสมกันแบบ LabelMe) — โปรเจกต์ Object Detection สำหรับความเสียหาย (วาด Box ตามข้อ 3 ข้างบน), โปรเจกต์ Instance Segmentation สำหรับโครงสร้าง (วาด Polygon ตามข้อ 2)
2. ถ้าภาพหนึ่งมีทั้งโครงสร้างและความเสียหาย — อัปโหลดภาพเดียวกันเข้าทั้ง 2 โปรเจกต์ แล้ว label เฉพาะส่วนที่ตรงกับโปรเจกต์นั้นในแต่ละที่

## Export

- **Roboflow:** export เป็น **YOLOv8** (โปรเจกต์ความเสียหาย) หรือ **YOLOv8 Segmentation** (โปรเจกต์โครงสร้าง) ได้ตรงๆ เลย — ได้ data.yaml พร้อมใช้ทันที **ไม่ต้องผ่าน COCO/สคริปต์แปลงเองอีกแล้ว** เพราะแยกโปรเจกต์ตามชนิดโมเดลไว้แล้วตั้งแต่ต้น (เปลี่ยนจากเดิมที่เคยใช้ COCO Segmentation + สคริปต์แยก class เอง — วิธีเดิมเลิกใช้แล้ว 2026-09-21)
- **LabelMe:** แปลงด้วย `labelme2yolo --json_dir <โฟลเดอร์ json> --output_format polygon --val_size 0 --test_size 0` (ปิดการแบ่ง train/valid/test อัตโนมัติ เพราะต้องแบ่งเองตามรอบบิน — ดู `การแบ่งชุดข้อมูล_train_valid_test.md`) — ได้ผลลัพธ์ที่ยัง**ผสม class กันอยู่** ต้องแยกเองต่อ (ดูหัวข้อถัดไป)

## แยกเป็น 2 ชุด (โครงสร้าง / ความเสียหาย) — **ใช้กับ LabelMe เท่านั้น** (Roboflow แยกไว้ตั้งแต่ต้นแล้วไม่ต้องทำขั้นนี้)

**ปัญหา:** ไม่มีระบบไหนรู้เองว่า class ไหนคือโครงสร้าง/ความเสียหาย ต้องกำหนดรายชื่อ 2 กลุ่มไว้เอง:
```
กลุ่ม B (ความเสียหาย) = Crack, Efflorescence, Exposed_Rebar, Honeycomb, Rust_Stain, Spalling
กลุ่ม A (โครงสร้าง)   = "ทุก class ที่ไม่ใช่กลุ่ม B" (ไม่ระบุรายชื่อตายตัว — กันพลาดถ้าเพิ่ม class โครงสร้างใหม่ทีหลัง เช่น Deck, Abutment จะเข้ากลุ่ม A อัตโนมัติโดยไม่ต้องแก้ list)
```
(กลุ่ม B คือรายชื่อจริงที่ใช้ในโปรเจกต์ — ตอนเขียนสคริปต์แยก class: เช็คว่า class อยู่ใน list กลุ่ม B ไหม → ถ้าใช่ = ความเสียหาย, ถ้าไม่ใช่ = โครงสร้าง โดย default ไม่ต้อง maintain list กลุ่ม A แยกอีกอัน)

**วิธีทำ:** แปลง JSON ของ LabelMe (ทุก class ปนกันตามปกติ) ด้วย `labelme2yolo` ก่อน แล้วใช้ **สคริปต์ของเราเอง** อ่านไฟล์ label ที่ได้ทั้งหมด แยกบรรทัดตาม class:
- class กลุ่ม A → เก็บเป็น polygon ต่อ (ไปเทรน YOLO-seg)
- class กลุ่ม B → **แปลง polygon → box เอง** (เอาจุดสุด min/max ของ polygon points) → ไปเทรน RT-DETR
- ถ้าใช้ Box tool วาดตรงๆ ตั้งแต่แรก (แนะนำในข้อ 3) จุดมุมที่ได้จะเป็นสี่เหลี่ยมพอดีอยู่แล้ว แปลงเป็น box แม่นยำ 100% ไม่มีทางพลาด

ภาพที่ไม่มี class ในกลุ่มไหนเลย ก็แค่ไม่มี label ในชุดนั้น ไม่ error — ภาพที่มีแต่โครงสร้าง (ไม่มีความเสียหาย) ควรใส่เข้าชุดความเสียหายด้วยแบบ "ไม่มี label เลย" เป็น background/negative example ช่วยลด false positive

## Augmentation

- เริ่มที่ **2-3 เท่า** (base) — สคริปต์รุ่นพี่ใช้ 2 เท่าเป็นฐาน + เพิ่มพิเศษ 4 เท่าสำหรับ class หายาก
- **Augment แค่ชุด train เท่านั้น ห้ามแตะ valid/test** (Roboflow ทำแบบนี้ให้อัตโนมัติอยู่แล้ว)
- เปิดแค่: **Horizontal Flip + Rotation มุมน้อย (±15°) + Brightness + Blur** พอ (ตรงกับที่สคริปต์รุ่นพี่ใช้แล้วได้ผลดี precision 0.91)
- **ห้าม Vertical Flip** (โครงสร้างกลับหัวดูผิดธรรมชาติ)
- **ระวัง Hue/Saturation กับ class ที่นิยามด้วยสี** (สนิม, คราบเกลือ) — เบามือเป็นพิเศษ หรือปิดไปเลย เพราะเปลี่ยนสีจะทำลายสัญญาณที่ใช้แยก class นั้น
- **Augmentation ทั่วไป (uniform multiplier) ไม่ช่วยแก้ความไม่สมดุลระหว่าง class** — สัดส่วนเดิมเท่าไหร่ก็ยังเท่าเดิมหลัง augment ถ้า class ไหนภาพน้อยจริงๆ ต้องหาภาพเพิ่ม หรือ oversample เฉพาะ class นั้นแยกในสคริปต์เอง

## เครื่องมือช่วย

- `move_batch.py` (ที่ root โปรเจกต์) — ย้ายภาพเป็นชุดๆ จากโฟลเดอร์ต้นทาง (เช่น ที่ดาวน์โหลดจากเน็ต) ไปโฟลเดอร์ปลายทาง แบบ move จริง (ไม่ใช่ copy) กันภาพซ้ำข้ามรอบ
- `dedupe.py` (ที่ root โปรเจกต์) — เช็ค/ลบไฟล์ซ้ำระหว่าง 2 โฟลเดอร์ (มี dry-run mode ปลอดภัยไว้ก่อน)

## จำนวนภาพเป้าหมาย

- เป้าหมายรอบแรก: **~200-600 ภาพรวม** พยายามให้แต่ละ class ความเสียหายมีอย่างน้อย **30-50 ตัวอย่าง**
- **ไม่ต้องรู้ล่วงหน้าว่า class ไหนภาพน้อย** — เทรนรอบแรกไปก่อน ดูผล (confusion matrix/recall รายคลาส) แล้วค่อยไปหาภาพเพิ่มเฉพาะ class ที่อ่อน (ดูรายละเอียดใน `การแบ่งชุดข้อมูล_train_valid_test.md`)
