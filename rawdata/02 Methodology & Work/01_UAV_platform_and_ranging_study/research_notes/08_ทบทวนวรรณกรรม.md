|---|---|
| ต้องบินใกล้แค่ไหน? | **อย่าบินใกล้ — ใช้ tele lens แทน** M4E telephoto (168 mm eq., 8192×6144) ได้ GSD ≈ 0.075 mm/px ที่ระยะ **3 m** ส่วนกล้อง wide (24 mm eq.) ต้องบินถึง **0.27 m** จึงจะได้ GSD เท่ากัน — อันตรายและ obstacle avoidance ไม่ยอม |

## 1. UAV + laser ranging module

### 1.1 งานหลัก: Sensors 2022, 22(12), 4469 (ที่โจทย์อ้างถึง)

Kuo-Wei Tian et al., *"Bridge Crack Inspection Efficiency of an Unmanned Aerial Vehicle System with a Laser Ranging Module"* — [PMC9227050](https://pmc.ncbi.nlm.nih.gov/articles/PMC9227050/) / [doi:10.3390/s22124469](https://doi.org/10.3390/s22124469)

**ระบบ**

| องค์ประกอบ | สเปก |
|---|---|
| UAV | multi-copter ประกอบเอง wheelbase 63 cm บินได้ **23 นาที** (ลดจาก 16 นาที baseline หลังติดเซนเซอร์ — ตัวเลขในเอกสารขัดกันเอง ควรเช็ค PDF) |
| กล้องตรวจสอบ | SONY DSC-RX0, 4800×3200 px, sensor 1", **f = 9.346 mm**, pixel pitch **0.00275 mm** |
| Laser ranging | **Lidar-100 จำนวน 4 ตัว** ติดที่มุมบน-ซ้าย/ล่าง-ซ้าย/บน-ขวา/ล่าง-ขวา ของกล้อง ความแม่น **±2 mm** สื่อสารผ่าน UART 19,200 baud |
| ประมวลผลบนบอร์ด | Raspberry Pi 4 |
| กล้องนำร่อง | fisheye แยกอีกตัว ยึดติดลำ |

**หลักการ 4 จุดเลเซอร์ (สำคัญที่สุดของงานนี้)** — ระยะทั้ง 4 ค่าถูกใช้ fit **สมการระนาบผิววัตถุ** `Ax + By + Cz + 1 = 0` แล้วรวมกับ camera calibration (f = 9.346 mm, principal point xo = 6.442 mm, yo = 4.506 mm, radial distortion k₁ = 0.0120, k₂ = −0.0229) ใช้ collinearity equations แปลง pixel → metric **พร้อมชดเชยกรณีกล้องไม่ตั้งฉากกับผิว** (object projection measurement method) นี่คือจุดขายจริง: laser 1 ตัวบอกได้แค่ระยะ, laser 4 ตัวบอกได้ทั้งระยะ **และมุมเอียง**

**ระยะทดสอบและ resolution**

ระยะที่ทดสอบ: ในร่ม 1, 2, 3 m (step 0.5 m); ภาคสนามสะพานจริง 3 เคส ที่ **4.6 m / 2.9 m / 2.5 m**

GSD ที่ระยะเหล่านี้ — **คำนวณเอง** จากสูตร `GSD = D × p / f = D × 0.00275 / 9.346`:

| ระยะ D | GSD (คำนวณเอง, mm/px) |
|---|---|
| 1.0 m | 0.294 |
| 2.0 m | 0.588 |
| 2.5 m | 0.735 |
| 2.9 m | 0.853 |
| 3.0 m | 0.883 |
| 4.6 m | 1.353 |

> ⚠️ **ยังไม่ยืนยัน:** การอ่านข้อความอัตโนมัติจาก PMC ได้ค่า ~2 เท่าของนี้ (0.582 mm/px ที่ 1 m) ค่าที่แสดงในตารางข้างบนมาจากสูตรตรง ๆ กับสเปกกล้องที่ paper ระบุเอง จึงน่าเชื่อกว่า แต่ **ต้องเปิด PDF ตัวจริงเช็คว่า paper รายงาน spatial resolution ไว้ที่เท่าไหร่** (MDPI block WebFetch — ต้องโหลดเอง)

**Error ที่รายงาน**

| การทดสอบ | Error |
|---|---|
| ในร่ม 3 m (control points บนผนัง) | max **6 mm**, relative **0.8%** |
| ในร่ม 3 m เป้า 1.0×1.0 m | max **7 mm**, relative **0.7%** |
| ในร่ม 3 m เป้า 2.0×2.0 m | max **19 mm**, relative **1.0%** |
| สนาม Case 1 (4.6 m) | crack ต่อเนื่อง error **6.1%**; crack ไม่ต่อเนื่อง กว้าง **3.9 mm** ยาว **0.412 m** |
| สนาม Case 2 (2.9 m) | error **3.0%** (ซ้าย), **1.8%** (ล่าง) |
| สนาม Case 3 (2.5 m) | error **0.8%** (ซ้าย), **0.0%** (ล่าง) |

**รอยแตกเล็กสุดที่วัดได้** — ตัวเลขนี้ **ขัดกัน** ระหว่างแหล่ง: บทคัดย่อ (ตามผลค้นหา) ระบุว่ายืนยันความแม่น "สำหรับรอยแตกกว้างกว่า **0.1 mm**" และอ้าง "**92% accuracy** ในการวัดความยาว" ขณะที่เนื้อความอ้าง Kim et al. ว่าแม่น "สำหรับรอยแตกกว้างกว่า **0.25 mm**" → **ยังไม่ยืนยัน ต้องอ่าน abstract + Section 5 ของ PDF จริง**

**Pipeline ประมวลผลภาพ** (ทั้ง 7 ขั้น เป็น classical CV ล้วน ไม่มี deep learning)
1. Grayscale ถ่วงน้ำหนัก `I = 0.2989R + 0.5870G + 0.1140B`
2. **Sauvola local thresholding** สองชุดพารามิเตอร์ — วัดความยาวใช้ window 180×180, k = 0.18; วัดความกว้างใช้ window 70×70, k = 0.42
3. กรอง noise ด้วย length-width ratio + object density
4. **Skeletonization ด้วย Zhang–Suen**
5. หา main skeleton ด้วย **Dijkstra shortest path** → ความยาว
6. Morphological erosion หา outline → วัดระยะตั้งฉากจาก skeleton → ความกว้าง
7. คูณด้วย mm/px

**ข้อจำกัดที่ผู้เขียนระบุเอง** (สำคัญมากสำหรับการวางแผนบิน)
- **ระยะวัดไม่ควรเกิน 3 m** และ **เป้าไม่ควรเกิน 1.0×1.0 m** จึงจะได้ความแม่นตามที่รายงาน
- error โตขึ้นชัดเจนเมื่อ > 3 m
- **"ไม่ได้ทำ visual test ด้วย UAV จริง"** — validation ใช้ control point ภาคพื้น ผู้เขียนแนะนำให้คนต่อยอด "สร้างรอยแตกจำลองบนผนังเอง" เพื่อเทียบ UAV vs manual → **นี่คือช่องว่างที่ senior project เข้าเสียบได้ตรง ๆ**
- laser 4 จุดสมมติผิวเป็นระนาบ (planar) — เสาตอม่อกลมจะละเมิดสมมติฐานนี้

## 2. Marker / known-object scale

### 2.1 หลักการและความแม่น

| วิธี | ความแม่นที่รายงาน | แหล่ง |
|---|---|---|
| Planar marker ติดผิวโครงสร้าง | relative error **1–2%** | อ้างใน [Automation in Construction 2023](https://www.sciencedirect.com/science/article/abs/pii/S0926580523001899) |
| Fiducial marker + **Harris corner detector** ประมาณ crack width **≤ 0.3 mm** | ปัจจัยเด่นคือ **จำนวนพิกเซล ไม่ใช่ GSD** — เพิ่มความแม่นได้ด้วยการเพิ่มจำนวนพิกเซล เพิ่ม focal length และคุม effective object distance | [Feasibility Study for the Fine Crack Width Estimation of Concrete Structures Based on Fiducial Markers](https://www.researchgate.net/publication/355829686_Feasibility_Study_for_the_Fine_Crack_Width_Estimation_of_Concrete_Structures_Based_on_Fiducial_Markers) |
| SfM + Known-size Marker (Liu et al. 2020) | จัดชั้นว่า **"mean error ≥ 0.1 mm"** (ไม่ผ่านเกณฑ์ sub-0.1 mm) และ **ไม่รองรับผิวไม่เป็นระนาบ** | Table 1, [arXiv 2501.09203](https://arxiv.org/pdf/2501.09203) |

### 2.2 ข้อสรุปเชิงวิศวกรรม — ทำไม marker ไม่ใช่คำตอบปฏิบัติการ

1. **ต้องเข้าถึงผิวเพื่อไปติด** — ซึ่งเป็นสิ่งที่ UAV มาแก้ตั้งแต่แรก วรรณกรรมระบุตรง ๆ ว่า *"การติด marker บนโครงสร้างที่เข้าถึงยากเป็นอันตรายด้านความปลอดภัย"* และ *"การหา scale factor ด้วย reference marker ที่รู้ค่าไม่ได้ทำได้เสมอในทางปฏิบัติ"*
2. **สร้างสิ่งรบกวน segmentation** — arXiv 2501.09203 พบว่า reflective marker สีเหลืองที่ติดไว้เพื่อ *อ้างอิงตำแหน่ง* กลับทำให้ baseline model segment ผิดอย่างมีนัยสำคัญ (ต้องพึ่ง SAM refinement ถึงจะรอด)
3. **แต่เป็น ground truth ที่ดีที่สุดสำหรับ validation** — ผู้เขียน arXiv 2501.09203 ใช้ marker เพื่อ relocate จุดที่วัดด้วย microscope Dino-Lite AF4915 เท่านั้น แล้วประกาศชัดว่า *"markers ... were not used by any step of the proposed pipeline. They are not necessary to achieve the reported accuracy"*

> **ข้อเสนอสำหรับ ku_project_jop:** ใช้ marker/scale bar เฉพาะบน **test pier ที่เข้าถึงได้** เพื่อสร้าง ground truth ตอน validate GSD ที่คำนวณจาก laser — ไม่ใช้ใน operational pipeline นี่จะเป็นส่วน "Experimental Validation" ที่ reviewer ชอบ และแก้ข้อจำกัดที่ Sensors 2022 ยอมรับเองว่าไม่ได้ทำ

## 3. Photogrammetry / 3D model แล้ววัดจากโมเดล

### 3.1 ผลวิจัยหลักที่ควรรู้ก่อนตัดสินใจ

**ข้อสรุปตรง ๆ: อย่าวัดความกว้างรอยแตกจาก mesh/point cloud ของ SfM**

จาก [arXiv 2501.09203 / ScienceDirect S1093968726025995](https://arxiv.org/pdf/2501.09203) (2025–2026) ระบุว่า SfM มี **"geometric accuracy typically at the centimeter level, which is insufficient to meet the requirements of detecting cracks at the millimeter scale"** และเสริมว่าใน SfM-based methods **"crack width is usually measured in the image domain under planarity assumptions, which decouples width measurement from its true 3D spatial location"** — แปลว่างานที่บอกว่า "วัดจาก 3D model" ส่วนใหญ่จริง ๆ แล้ววัดจากภาพ 2D แล้วเอาไป map ลง 3D ทีหลัง

### 3.2 การเปรียบเทียบเชิงตัวเลขของ 3 วิธี reconstruct (Table 7, arXiv 2501.09203)

### 3.4 งาน photogrammetry อื่นที่เกี่ยวข้อง

| งาน | สาระ |

### 3.5 สถาปัตยกรรมที่วรรณกรรมชี้ว่าถูกต้อง

**แยกงานเป็น 2 สเกล:**
- **สเกลหยาบ (3D/stitching):** ใช้กล้อง wide + SfM/SLAM ทำ "แผนที่" ของเสาตอม่อ เพื่อ **บอกตำแหน่ง** ของความเสียหาย และเป็น container ให้ผลลัพธ์ (นี่คือสิ่งที่ Gou et al. 2026 ใน rawdata ของโปรเจกต์เรียกว่า *coding system + spatial coordinate framework*)
- **สเกลละเอียด (วัดความกว้าง):** ใช้กล้อง tele ถ่ายภาพความละเอียดสูงที่ระยะควบคุม + laser scale → วัดจากภาพ 2D → **map ค่ากลับเข้า 3D** ไม่ใช่วัดจาก 3D

### 4.2 การแปลง mask → ความกว้างจริง (mask-to-width)

**ขั้นตอนมาตรฐาน 4 ขั้น**

1. **Skeletonization** — Zhang–Suen thinning ให้ centerline หนา 1 px (Sensors 2022, Kim 2017 ใช้ตัวนี้ทั้งคู่)
2. **Orthogonal / normal-direction width** — ที่ทุกจุดบน skeleton หาทิศ tangent แล้ววัดระยะไปยังขอบทั้งสองข้างตาม **normal** ไม่ใช่แนวนอน/แนวตั้ง นิยามทางวิศวกรรมตาม AutCon 2026 คือ *"the shortest physical distance between the two crack boundaries measured along the local normal direction at the crack centerline"*
3. **Sub-pixel edge** — สำคัญเมื่อรอยแตกกว้าง 3–8 px วิธีที่พบ: Canny + interpolation (Applied Sciences 2022), boundary refinement transformer (IBR-Former), Euclidean Distance Transform-based width consistency check (arXiv 2501.09203)
4. **Scale conversion** — คูณด้วย mm/px จาก laser/marker/calibration board

**ความแม่นที่รายงานของขั้นตอนนี้**

| วิธี | ตัวเลข | หมายเหตุ |
|---|---|---|
| Orthogonal skeleton analysis ทั่วไป | measurement accuracy **> 90%** | ผลค้นหาทั่วไป — ยังไม่ยืนยันแหล่ง |
| Li et al., *CACAIE* 2024 [doi:10.1111/mice.13344](https://onlinelibrary.wiley.com/doi/10.1111/mice.13344) | length **mean relative error 1.3%**, width **median absolute error < 0.15 mm** | pavement |
| 3D semantic point cloud (arXiv 2501.09203) | ME **0.09 mm**, mean RE **14.37%**, AE ทุกค่า **< 0.2 mm** | เห็นตารางเต็มในหัวข้อ 3.3 |
| MCMamba + MLS scale field | **< 10% error สำหรับ crack < 0.2 mm** | บน UAV จริง |

**ข้อควรระวังที่วรรณกรรมชี้:** *"conventional orthogonal projection methods ... performance may degrade in regions with high curvature or branching"* — รอยแตกที่แตกแขนง (map cracking, ซึ่ง BMMS นับเป็นความเสียหายแยกประเภท) จะทำให้ orthogonal width พัง

### 4.3 ตัวเลข reality check ที่ต้องรู้ (จาก rawdata ของโปรเจกต์เอง)

Çelik, Hoskere & Kessler, *"From pixels to rating"*, [CACAIE, doi:10.1111/mice.70145](https://onlinelibrary.wiley.com/doi/10.1111/mice.70145) (รับ 30 ต.ค. 2025) — อยู่ใน `rawdata/01 Literature Review/3_Gap+Method/`

- Dataset: **2,070 ภาพ annotate เอง** (1,535 จากโครงสร้างคอนกรีตหลากหลาย + 289 crack images จาก BCDS ขนาด 512×512, ที่เหลือ resize เป็น 1024×1024)
- Multi-damage segmentation ด้วย **FPN + EfficientNet-B2** (ชนะ U-Net, SegFormer, DeepLabV3 ในการทดสอบของเขา) ได้ **mean IoU เพียง 20.6%**
- ต่อ class: corrosion **26.8%**, rust flag 24.8%, efflorescence 24.2%, spalling/moss 23.8%, **crack เพียง 20.1%**, honeycomb **2.1%** (ไม่เรียนรู้อะไรเลย)
- Recall 37.2% > Precision 31.1% → false positive เยอะกว่า false negative
- ตรงข้าม: โมเดล **BiLSTM ที่แปลง *ข้อความ* บันทึกตรวจสอบ → condition rating ได้ macro F1 ถึง 96.4–99.9%** (traffic safety test macro F1 = **96.4%**) แต่ durability network ได้เพียง **71.5%**

> **นี่คือช่องว่างที่แท้จริงของสาขา:** segmentation หลายความเสียหายบนภาพตรวจสอบจริง (ไม่ใช่ benchmark สะอาด) ยังอยู่แค่ IoU ~20% ขณะที่ตัวเลข 0.84 F1 ของ SCSegamba มาจาก benchmark dataset ที่รูปเป็นภาพระยะใกล้เกือบทั้งหมด **อย่าเอาตัวเลข benchmark ไปอ้างว่าจะได้บนภาพ UAV สนามจริง**

### 5.2 ประเมินตรง ๆ ว่า MLLM ทำอะไรได้/ไม่ได้ตอนนี้

**ทำได้ดี**
- **บรรยาย** ความเสียหายเป็นภาษาธรรมชาติ และ **ให้เหตุผลเชื่อมโยง** damage → condition rating (SDIGLM 95.24%)
- **Annotation assistant** — ลดต้นทุน labeling ได้จริง (85–98% accuracy)
- **ทำ text-based condition rating** ซึ่งเป็นส่วนที่แม่นที่สุดของทั้ง pipeline (Çelik: macro F1 96.4%)

**ทำไม่ได้ (สำคัญมากสำหรับ scope โปรเจกต์)**
- **ไม่มีงานใดเลยที่ MLLM วัดความกว้างรอยแตกเป็นมิลลิเมตรได้** MLLM ไม่มี metric scale — จะรู้ว่า 1.6 mm หรือ 3.2 mm ไม่ได้ ถ้าไม่มีคนป้อนค่าที่วัดมาแล้วให้
- **ยังไม่มี benchmark agreement กับ inspector มนุษย์** ที่รายงานเป็น Cohen's kappa / weighted kappa บน condition rating — ช่องว่างชัดเจน

> **สถาปัตยกรรมที่วรรณกรรมชี้:** วัดด้วย CV → **ป้อนตัวเลข mm เข้า MLLM** → ให้ MLLM ทำ reasoning เทียบเกณฑ์ BMMS/AASHTO → ออก condition state + เหตุผล นี่คือสิ่งที่ SDIGLM ทำ (U-Net เป็น visual CoT ให้ VLM) และคือที่ที่ T-BHI ของโปรเจกต์เสียบเข้าได้พอดี

### 6.2 ช่องว่าง dataset ที่ใหญ่ที่สุด (และคือโอกาสตีพิมพ์)

**ไม่มี public dataset ใดเลยที่มี label ความกว้างรอยแตกเป็นมิลลิเมตร พร้อมระยะกล้อง/GSD กำกับ**

ทุก dataset ข้างบนเป็น binary mask หรือ class label เท่านั้น ผลคือ:
- โมเดล segmentation ทั้งหมด train บน mask ที่ไม่รู้ว่ากว้างจริงกี่ mm
- ไม่มีวิธี benchmark "mask → mm" ข้ามงาน — ทุกงานสร้าง ground truth microscope ของตัวเอง (arXiv 2501.09203 ใช้ Dino-Lite AF4915 วัดทุก ~10 mm ตามแนวรอยแตก)
- Sensors 2026 ระบุตรง ๆ ว่า dataset ที่ใช้ *"was not acquired using UAV platforms"* และ *"does not reflect UAV-specific imaging effects such as motion-induced blur ... or illumination changes"*

> **นี่คือ contribution ที่ senior project ทำได้จริงและตีพิมพ์ได้:** dataset ภาพเสาตอม่อจาก UAV ที่ทุกภาพมี (ก) ระยะกล้อง-วัตถุจาก laser (ข) GSD ที่คำนวณและ verify แล้ว (ค) ความกว้างรอยแตกจริงจาก crack comparator/microscope (ง) BMMS damage level 0–5 ที่ inspector ให้ ต่อให้มีแค่ 200–500 ภาพก็เป็นของใหม่

### 7.2 ย้อนกลับกำหนด GSD — คำนวณเอง

**หลักฐานเชิงประจักษ์ว่า "กี่พิกเซลถึงจะพอ"** จาก [Sensors 26(3):1031 (2026)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12900104/) วิเคราะห์ U-Net บน 11,200 ภาพ แยกตามความหนารอยแตกเป็นพิกเซล:

| ความหนา (px) | mean discrepancy (px) | SD (px) | mIoU | Dice | สรุปของผู้เขียน |
|---|---|---|---|---|---|
| **≤ 3** | 5.38 | 5.13 | **0.14** | 0.21 | *"largest relative instability"*, high dispersion |
| **4–7** | 5.00 | 5.24 | **0.29** | 0.41 | *"comparatively more stable behavior"* |
| **≥ 8** | 5.44 | — | **0.40** | 0.53 | เสถียรที่สุด |

ผู้เขียนสรุปนโยบายการวางแผนบินไว้ชัด: *"Selecting a GSD that ensures cracks of interest are represented by a sufficient number of pixels is more critical than pursuing minimal GSD values at the expense of increased operational and processing costs"* และเตือนว่า *"pixel-level crack thickness derived from segmentation masks should not be interpreted as a reliable estimator of physical crack width"*

**ตาราง GSD ที่ต้องการ (คำนวณเอง: `GSD ≤ crack_width / N_px`)**

| เกณฑ์ที่ต้องตัดสิน | ความกว้าง | GSD ที่ N=4 px (ขั้นต่ำสุด) | GSD ที่ N=8 px (แนะนำ) | GSD ที่ N=2 px (แค่ *ตรวจพบ* ไม่วัด) |
|---|---|---|---|---|
| BMMS ระดับ 4↔3 (**boundary ที่ตัดสินบ่อยที่สุด**) | 1.6 mm | **0.40 mm/px** | **0.20 mm/px** | 0.80 mm/px |
| BMMS ระดับ 3↔2 | 3.2 mm | 0.80 | 0.40 | 1.60 |
| BMMS ระดับ 2↔1 | 4.8 mm | 1.20 | 0.60 | 2.40 |
| AASHTO RC CS1↔CS2 | 0.3 mm | **0.075 mm/px** | **0.038 mm/px** | 0.15 mm/px |
| AASHTO RC CS2↔CS3 | 1.3 mm | 0.33 | 0.16 | 0.65 |
| AASHTO PC CS1↔CS2 | 0.1 mm | **0.025 mm/px** | 0.013 | 0.05 |
| ACI water-retaining | 0.10 mm | 0.025 | 0.013 | 0.05 |

**ตรวจสอบข้ามกับวรรณกรรม:** Sensors 2026 คำนวณเองว่าถ้าจะให้รอยแตก 0.2–0.3 mm มี ≥ 4 px ต้องได้ GSD **≈ 0.05–0.075 mm/px** ซึ่ง *"achievable only at flight distances < 4 m with their camera system"* — ตรงกับตารางข้างบนพอดี ✓

| GSD เป้า | Wide (24 mm) | Medium Tele (70 mm) | **Telephoto (168 mm)** |

| วิธีวัดระยะ | ความแม่นสเปก | error ที่ 2 m | ที่ 3 m | ที่ 5 m | ผลต่อรอยแตก 1.6 mm |

| Benewake **TFmini Plus** (11 g) | ±50 mm @ 0.1–5 m, ±1% @ >6 m | ±2.5% | ±1.7% | ±1.0% | ±0.027 mm |

|---|---|---|

> **ข้อสรุปที่ไม่ตรงสัญชาตญาณ และเป็นจุดขายของรายงาน:** ที่ระยะ 3–5 m **ความแม่นของการวัดระยะไม่ใช่คอขวด — segmentation edge error คือคอขวด** DJI LRF ที่ให้ ±6.8% ที่ 3 m ยังหยาบกว่า segmentation error ±12.5% อยู่ครึ่งหนึ่ง จึงพอใช้ได้สำหรับ *จำแนกระดับ BMMS* แต่ถ้าจะรายงานค่าความกว้างสัมบูรณ์เพื่อ trend monitoring ควรอัปเกรดเป็น laser 4 จุดขนาน (scale จากระยะห่างจุด ไม่ใช่ ToF) หรือติด TFmini Plus เสริม

| **Error budget แยกส่วน** | δw_total² = δw_range² + δw_seg² + δw_tilt² + δw_blur² พร้อมตัวเลขแต่ละพจน์ | **ยังไม่มีงานไหนทำ** — ทุกงานรายงานแต่ error รวม ทำให้ไม่รู้ว่าควรลงทุนแก้อะไรก่อน นี่คือ contribution ที่ทำได้ด้วยการทดลองง่าย ๆ |
| **ผลของมุมตกกระทบ (tilt)** | error vs มุม 0°/15°/30°/45° | เสาตอม่อกลม → มุมเปลี่ยนตลอด สมมติฐาน planar ของ laser 4 จุดพัง; Sensors 2022 ยอมรับข้อจำกัดนี้เอง |
| **ผลของ motion blur** | error vs shutter speed / ความเร็วบิน | Kim 2017 ใช้ 1/1000 s; Sensors 2026 ระบุว่า dataset ที่ใช้ *"does not reflect UAV-specific imaging effects such as motion-induced blur"* → เป็นช่องว่างเปิด |
| **Repeatability** | บินซ้ำจุดเดิม 3 รอบ รายงาน SD ของความกว้างที่วัดได้ | ไม่มีงานไหนรายงาน แต่คือสิ่งที่กรมทางหลวงจะถามข้อแรก |
| **เวลาและต้นทุน** | นาที/เสา, ภาพ/เสา, นาทีประมวลผล เทียบการตรวจแบบ manual | Sensors 2022 **ยอมรับเองว่าไม่ได้ทำการเทียบนี้** ทั้งที่ชื่อ paper มีคำว่า "Efficiency"; Sensors 2026 ทำแล้วสำหรับ photogrammetry (52 hr @ GSD 0.72 mm/px vs 3 hr @ 6.24 mm/px) |
| **การเปรียบเทียบกับ SOTA ปัจจุบัน** | เทียบกับ **MCMamba (error ≤ 10% @ crack < 0.2 mm)** และ **Ding 2023 (< 0.2 mm)** | ถ้าไม่ชนะ ต้องอธิบายว่าชนะด้านอื่น (ราคา, ความง่าย, เชื่อมมาตรฐานไทย) |

### 8.3 ช่องว่างที่ยังว่างอยู่จริง (เรียงตามโอกาสสำเร็จของ ป.ตรี)

1. **★★★ Dataset เสาตอม่อจาก UAV ที่มี label ความกว้างเป็น mm + GSD + BMMS level** — ไม่มีใครทำ ทำได้ด้วยทรัพยากร ป.ตรี และเป็นสิ่งที่ทุกงานหลังจากนี้ต้องใช้
2. **★★★ Error budget แยกส่วนสำหรับ UAV crack measurement** — เป็นงานวิเคราะห์ล้วน ไม่ต้องสร้างโมเดลใหม่
3. **★★☆ เชื่อม CV measurement → MLLM reasoning → BMMS/T-BHI** — SDIGLM พิสูจน์แล้วว่าทำได้ (95.24%) แต่ยังไม่มีใครทำกับมาตรฐานไทย และ **ไม่มีใครแก้ปัญหา "รอยแตกจากแรงเฉือน/แรงดัด ทุกขนาด = ระดับ 1"** ซึ่งต้องใช้ pattern reasoning ไม่ใช่การวัด
4. **★★☆ Validation UAV vs manual inspection บนผนังที่สร้างรอยแตกจำลอง** — ผู้เขียน Sensors 2022 แนะนำเองว่าเป็นงานต่อยอด และยังไม่มีใครทำ
5. **★☆☆ Two-scale flight planning (wide สำหรับ 3D + tele สำหรับ width)** — เป็นวิศวกรรมระบบมากกว่าวิจัย แต่ทำให้ demo น่าเชื่อ

### 8.4 ตัวเลขเป้าที่ผมแนะนำให้ตั้ง (ตั้งจากข้อมูลข้างบน ไม่ได้เดา)

```
ระยะบิน                 3.0–4.0 m (telephoto 168 mm eq.)
GSD เป้า                 ≤ 0.10 mm/px  (verify ด้วย target จริง)
ความแม่นวัดระยะเป้า        ≤ ±2% ที่ 3 m  (DJI LRF ให้ ±6.8% → ต้องเสริม)
Crack width MAE เป้า      ≤ 0.15 mm     (SOTA 3D fusion = 0.09 mm)
Crack width MAPE เป้า     ≤ 15%         (SOTA 3D fusion = 14.37%)
รอยแตกเล็กสุดที่ตรวจพบ     0.2 mm @ POD ≥ 90%  (KTH ได้ 0.1 mm @ POD 97% ในสภาพควบคุม)
Segmentation IoU เป้า     ≥ 0.60 บน test set ตัวเอง
                          (benchmark SOTA 0.85 แต่บนภาพตรวจสอบจริง Çelik ได้แค่ 0.20)
BMMS level weighted κ     ≥ 0.70        (ยังไม่มี baseline ในวรรณกรรม — ตั้งเอง)
```

**หมายเหตุความซื่อสัตย์ที่สำคัญที่สุด:** ถ้าเป้า IoU ที่ตั้งไว้คือ 0.85 แบบ benchmark **จะไม่มีทางถึง** เพราะภาพ UAV ของเสาตอม่อจริงมี background รก แสงไม่คุมได้ และ blur — Çelik ที่ตีพิมพ์ใน CACAIE (Q1) ได้ mean IoU **20.6%** บนภาพตรวจสอบจริง 2,070 ภาพ ตั้งเป้าที่ 0.60 บน test set ของตัวเองแล้วอธิบายช่องว่างนี้ จะดูเป็นงานวิจัยที่เข้าใจปัญหามากกว่าตั้ง 0.85 แล้วไม่ถึง
