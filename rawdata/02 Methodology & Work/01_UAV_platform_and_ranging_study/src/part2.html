DJI SDK — เขียนโปรแกรมอะไรได้ อะไรไม่ได้

ภาพรวม: เขียนได้ 2 ที่เท่านั้น

คำถามตั้งต้นคือ "ลง software แยกลงโดรน DJI ได้ไหม เช่น software บังคับการบิน การวัดระยะ" คำตอบขึ้นกับว่า "ลง software ลงโดรน" หมายถึงอะไร

สิ่งที่อยากทำทำได้ไหมทำอย่างไร / ทำไมไม่ได้
แอปควบคุมการบินของตัวเอง (แทน DJI Pilot 2)ได้เขียนแอป Android ด้วย Mobile SDK V5 — แอปรันบนแท็บเล็ต/มือถือที่ต่อกับรีโมต ไม่ได้รันบนตัวโดรน
ต่ออุปกรณ์ของตัวเอง (เซนเซอร์ กล้อง คอมพิวเตอร์) เข้ากับโดรนได้เขียนโปรแกรมฝั่ง payload ด้วย Payload SDK V3 ผ่านพอร์ต E-Port / SkyPort — โปรแกรมรันบนคอมพิวเตอร์ที่คุณแขวนไว้กับโดรน
บินอัตโนมัติตามเส้นทางที่กำหนดเองได้สร้างไฟล์ KMZ/WPML เองแล้วส่งเข้า flight controller ผ่าน MSDK (IWPMZManager + IWaypointMissionManager)
ส่งคำสั่งบังคับแบบเรียลไทม์จากโค้ดได้Virtual Stick — ส่งคำสั่งที่ความถี่ 5–25 Hz แต่มีข้อจำกัดมาก (ดู 2.2)
อ่านค่าระยะจากเซนเซอร์กันชนได้IPerceptionManager.addObstacleDataListener() คืนระยะเป็นมิลลิเมตร (แต่ไม่มีสเปกความแม่นยำ — ดูบทที่ 3)
อ่านค่าจาก laser rangefinderได้ผ่าน KeyLaserMeasureInformation ใน KeyManager (MSDK 5.1.0 ขึ้นไป)
เขียนโค้ดรันบน flight controller / แก้ firmwareไม่ได้flight controller เป็นระบบปิดสนิท ไม่มี SDK ระดับนั้น และการ reverse engineer ผิดเงื่อนไข EULA
ปิด geofence / บินในเขตห้ามไม่ได้ระบบ GEO บังคับที่ firmware — SDK ให้แค่อ่านข้อมูลเขต ไม่ให้แก้
เปลี่ยน EKF / อัลกอริทึม positioningไม่ได้ปิดสนิท — ถ้าต้องการระดับนี้ต้องไปทาง PX4/ArduPilot (ดูบทที่ 7)
สรุปเป็นประโยคเดียว DJI ให้คุณเขียนโปรแกรมได้ รอบ ๆ ตัวโดรน (บนรีโมต และบน payload) แต่ไม่ให้เข้าไป ใน ตัวโดรน — เพียงพออย่างยิ่งสำหรับโปรเจกต์นี้ เพราะสิ่งที่ต้องการคือการวางแผนบิน ถ่ายภาพ และอ่านค่าเซนเซอร์ ไม่ใช่การเปลี่ยนวิธีที่โดรนรักษาสมดุล

Waypoint Mission — สิ่งที่ต้องรู้ก่อนเขียน

ไฟล์ KMZ คือไฟล์ zip ที่ข้างในต้องมี template.kml และ waylines.wpml — ชื่อไฟล์ zip ตั้งเองได้ แต่ชื่อไฟล์ข้างในเปลี่ยนไม่ได้ และ firmware จะ execute waylines.wpml ไม่ใช่ template.kml (ถ้า generate มาแต่ template.kml mission จะไม่วิ่ง — เป็นบั๊กยอดฮิต)

การขอ App Key

  1. สมัคร developer account ที่ developer.dji.com/register — ต้อง verify ด้วยอีเมล + บัตรเครดิตหรือเบอร์โทร (บัตรไม่ถูกตัดเงิน)
  2. Apps → Create App → กรอกชื่อ แพลตฟอร์ม package identifier หมวดหมู่ คำอธิบาย
  3. package identifier ต้องตรงกับ applicationId ใน Gradle เป๊ะ ๆ ผิดตัวเดียว register ไม่ผ่าน
  4. ใส่ App Key ใน AndroidManifest.xml เป็น meta-data com.dji.sdk.API_KEY
ข้อควรระวังสำหรับงานภาคสนาม MSDK ต้องต่ออินเทอร์เน็ตเพื่อยืนยัน App Key กับเซิร์ฟเวอร์ของ DJI — เครื่องที่ยังไม่เคย activate จะ register ไม่ผ่านถ้าไม่มีเน็ต
สะพานในชนบทมักไม่มีสัญญาณ ต้อง activate จากที่ทำงานให้เรียบร้อยก่อนออกภาคสนามเสมอ

การวัดระยะจากโดรนถึงผิววัตถุ

คำตอบก่อนอ่านรายละเอียด มี 5 ทางที่โดรนจะรู้ระยะห่างจากผิววัตถุ และ ไม่มีทางไหนแม่นพอสำหรับแปลง pixel เป็นมิลลิเมตรที่ระยะใกล้
สาเหตุร่วมคือ laser rangefinder ของ DJI ทุกรุ่นมี พจน์คงที่ ±0.2 m ในสูตรความแม่น ซึ่งไม่ลดลงตามระยะ → ยิ่งบินใกล้ ความคลาดเคลื่อนสัมพัทธ์ยิ่งแย่ ตรงข้ามกับสัญชาตญาณ

2. มี issue เปิดค้างบน GitHub (dji-sdk/Mobile-SDK-Android-V5 #368) รายงานว่าปรับ targetPoint แล้วค่าระยะไม่เปลี่ยน ไม่ว่าจะเล็งจุดไหนบนจอ และยังไม่มีคำตอบจาก DJI — แปลว่าสมมติฐาน "เล็งเลเซอร์ไปที่รอยแตกโดยตรง" อาจทำไม่ได้จริง ต้องทดสอบเองก่อนออกแบบระบบรอบมัน

RTK

ทุกรุ่น DJI Enterprise ให้ตัวเลขเดียวกันเมื่อได้สถานะ RTK FIX: แนวราบ 1 cm + 1 ppm, แนวดิ่ง 1.5 cm + 1 ppm (1 ppm = 1 mm ต่อระยะห่างจากสถานีฐาน 1 กม.)

RTK ใช้กับโจทย์นี้ไม่ได้ ด้วยเหตุผลเชิงโครงสร้าง 3 ข้อ 1. RTK บอกตำแหน่งของโดรน ไม่ได้บอกระยะถึงผิววัตถุ — จะได้ระยะต้องรู้ตำแหน่งของผิวคอนกรีตในระบบพิกัดเดียวกันด้วย ซึ่งต้องมี as-built survey หรือ BIM ที่แม่นกว่านั้น
2. ใต้ท้องสะพานคือสภาพแวดล้อม GNSS-denied โดยนิยาม — ท้องคานบังท้องฟ้าไปเกือบหมด
3. Multipath — เสาคอนกรีตและโครงเหล็กสะท้อนสัญญาณ ทำให้ระยะที่วัดได้ยาวเกินจริงโดยที่ตัวรับไม่รู้ตัว

งานวิจัยรายงานว่า RTK fix ล้มเหลวบ่อยเมื่ออยู่ห่างสิ่งกีดขวางในระยะ 0–5 m และใช้เวลา re-fix ประมาณ 9–13 วินาทีหลังพ้นสิ่งกีดขวาง ควรยืนยันตัวเลขในเปเปอร์ต้นฉบับก่อนอ้างในเล่ม
