## 1. รายงานวิจัยฉบับสมบูรณ์_วช68 — ภาพรวมโครงการแม่

โครงการใหญ่มี 4 องค์ประกอบ:
1. **S-BCRI** (Simple Bridge Corrosion Risk Index) — คัดกรองความเสี่ยงกัดกร่อนระดับเครือข่าย
   จากฐานข้อมูล BMMS (ไม่ต้องลงพื้นที่ใหม่)
2. **Hybrid Surveying / Digital Twin** — UAV + Terrestrial LiDAR + Handheld SLAM สร้างโมเดล 3 มิติ
   ของสะพานกรณีศึกษา (พื้นที่นำร่อง)
3. **YOLOv10 ตรวจจับความเสียหายจากภาพ** — ใกล้เคียงงาน T-BHI ที่สุด (ดูรายละเอียดด้านล่าง)
4. **3D Nonlinear FEM** — เอาผล AI ไปวิเคราะห์เสถียรภาพโครงสร้างจริง (เจาะจุด half-joint/Gerber
   connection ของสะพาน)

ระยะเวลาโครงการ: 12 เดือน (7 มี.ค. 2568 – 6 มี.ค. 2569), รายงานนี้ครอบคลุมผลงาน 11 เดือนแรก

### 1.1 ส่วน YOLOv10 (section 3.5, 4.4-4.5) — ส่วนที่เกี่ยวข้องกับ T-BHI มากที่สุด

**คลาสความเสียหาย (4-5 คลาส):** Crack (รอยแตก), Erosion (การกัดกร่อน), Spalling (การกะเทาะ),
Steel Exposure (เหล็กเสริมโผล่), (+ Efflorescence/คราบเกลือ ในชุดข้อมูลหลัง)

**กฎการ label ที่ใช้จริง (section 3.5.3.2.1):**
- กรอบต้องตึงชิดขอบเสียหายจริง (Tight Bounding Box) ลดพื้นที่ background ในกรอบ
- ความเสียหายประเภทเดียวกันที่ติดกันต่อเนื่อง = 1 กรอบ, แยกกันชัดเจน = คนละกรอบ
- **Spalling**: 1 กรอบครอบพื้นที่กะเทาะทั้งหมดที่ต่อเนื่องกัน
- **Steel Exposure**: ต้อง label กรอบ Spalling ครอบก่อน แล้วมีกรอบ Steel Exposure ซ้อนเพิ่ม
  เฉพาะเส้นเหล็กที่มองเห็นแต่ละเส้นภายในกรอบ Spalling นั้น
- **Crack**: กรอบแคบที่สุดเท่าที่ทำได้ นับเฉพาะรอยที่ต่อเนื่องชัดเจน ยาว ≥ 5-10 ซม.
- **Erosion / Efflorescence**: 1 กรอบครอบพื้นที่ต่อเนื่องทั้งหมด

**Data augmentation ที่ทดลอง:** Horizontal Flip, Rotation ±15°, Brightness ±40%; ชุดหลังทดลอง
เพิ่ม Shear และ Exposure(brightness) แยกทีละชุด

**ผลลัพธ์เชิงปริมาณ:** mAP@0.5 จาก baseline 26.5% → 46.7% (Phase 2) — แต่ trade-off ต่างกันตามชุด
augmentation: เพิ่ม Shear ช่วย recall (32.4%→53.5%) แต่เพิ่ม Exposure(brightness) กลับทำให้ precision
ตกและ Efflorescence/Cracking detection แย่ลง

### 1.2 ⭐ Table 15 — เกณฑ์ระดับความเสียหาย 5 ระดับ (แยก RC/PC ชัดเจน พร้อมตัวเลข mm)

จาก section 4.5 "การประยุกต์ใช้แบบจำลองเพื่อประเมินระดับความเสียหายของโครงสร้าง" เทียบกับคู่มือกรมทางหลวง
(DOH) — **นี่คือเกณฑ์ขนาดความเสียหายที่นำไปใช้เขียน `damage_rules.py` ได้โดยตรง:**

| ระดับ | สภาพ | เกณฑ์ |
|---|---|---|
| 5 ดีมาก | ผิวใหม่ ไม่มีความเสียหาย | — |
| 4 ดีพอใช้ | สึกผิวเล็กน้อย มีรอยแตกลายงา/hairline ยังไม่ถึงเหล็กเสริม | width < 1.6 mm (RC) / < 0.10 mm (PC) |
| 3 พอใช้ | กะเทาะปานกลาง เห็นหินแต่ยังไม่ถึงเหล็ก | spalling depth 5–10 mm; width 1.6–3.2 mm (RC) / 0.10–0.23 mm (PC) |
| 2 ชำรุด | กะเทาะลึก เห็นเหล็กเสริมเริ่มสนิม | spalling depth 10–20 mm; width 3.2–4.8 mm (RC) / 0.25–0.76 mm (PC) |
| 1 วิกฤต | กะเทาะลึกมาก เหล็กสนิมหนัก/ขาด กระทบเสถียรภาพ | spalling depth > 20 mm; width > 4.8 mm (RC) / > 0.76 mm (PC) |

**หมายเหตุสำคัญ:** ค้นทั้งไฟล์แล้ว **ไม่พบคำว่า "คู่มือเริ่มต้นโปรเจกต์ประเมินสะพานจากภาพโดรน" หรือ
"T-BHI"/"EHI"** ที่ [`PROJECT_SUMMARY.md`](../../PROJECT_SUMMARY.md) เคยอ้างถึง (section 4.4-4.8) —
แปลว่าเป็นคนละเอกสาร ยังไม่มีอยู่ในโฟลเดอร์นี้ ต้องหามาเพิ่ม หรือใช้ Table 15 นี้อ้างอิงแทนไปพลางก่อน

### 1.3 บริบทอื่น (สรุปสั้น ไม่ใช่ประเด็นหลักของ T-BHI)

- **S-BCRI** = ESI × SVI, ESI = 0.60·Cl′ + 0.40·RH′, SVI = 0.70·Damage′ + 0.30·Age′ (normalize 0-1)
  ใช้กับฐานข้อมูล 9,629 สะพานทั่วประเทศ → high risk 7 สะพาน, low risk 9,466 สะพาน
- **3D-FEM (section 4.5-4.6):** วิเคราะห์จุด half-joint (คานปลายบาก) ของสะพาน เทียบโมเดล intact vs
  damaged (จากผล AI) พบว่าโมเดล damaged รับโหลดได้น้อยกว่าเดิม ~34% ก่อนเปลี่ยนโหมดวิบัติจาก
  ดัด (ductile) เป็นเฉือนตรง (brittle)

## 2. โปรเจกต์รุ่นพี่ (3D Point Cloud) — เฉพาะส่วนที่ไม่ผูกกับ Point Cloud

> ตัดกลไก pipeline point cloud/mesh/plane-capture ทั้งหมดออก เพราะไม่เกี่ยวกับงานที่ใช้ภาพถ่าย 2D
> เก็บเฉพาะสูตรให้คะแนนซึ่งไม่ขึ้นกับแหล่งที่มาของข้อมูล (ใช้ได้ทั้งจาก point cloud หรือภาพถ่ายตรงๆ)

**คลาสความเสียหาย (4 คลาส, section 4.7.1):** Cracking, Spalling, Rebar Exposure, Honeycomb
(ตรวจจับด้วย Google Gemini 3 Pro เป็น VLM zero-shot ผ่าน Roboflow ไม่ใช่โมเดลเทรนเอง)

**DOH Rating (section 4.8)** — วัดจาก crack width อย่างเดียว ไม่แยก RC/PC (หยาบกว่า Table 15 ด้านบน):

| Rating | ระดับ | ค่าวัด |
|---|---|---|
| 5 | ดีมาก | = 0 mm |
| 4 | ดีพอใช้ | ≤ 0.1 mm |
| 3 | พอใช้ | ≤ 0.3 mm |
| 2 | ชำรุด | ≤ 0.76 mm |
| 1 | วิกฤต | > 0.76 mm |

**Priority Index (Pellegrini Algorithm, section 4.9):**

```
Priority Index (PI) = Condition Value (CV) × Component Weight × Defect Criticality Weight
CV = 5 − DOH Rating
```

**Component Weight (Table 7):** Girder / Pier / Cap Beam / Footing / Abutment / Bearing = 1.5,
Deck / Expansion Joint = 1.2, Diaphragm = 1.0, Railing / Barrier / Drainage = 0.8

**Defect Criticality Weight (Table 8):** Shear Crack 1.5, Settlement 1.4, Scour 1.4,
Flexural Crack 1.2, Corrosion 1.2, Spalling 1.1, Surface Crack 0.8, Staining 0.5

**PI → ระดับความเร่งด่วน (Table 9):** PI ≥ 9.0 → วิบัติ(0) ปิดใช้/รื้อสร้างใหม่ทันที ... PI < 1.0 →
ดีมาก(5) ตรวจทุก 2 ปี (ตารางเต็มดูใน [`โปรเจกต์ป.ตรี ปีที่แล้ว_203499.pdf`](โปรเจกต์ป.ตรี%20ปีที่แล้ว_203499.pdf)
section 4.9)

**⭐ TSR (Total Severity Rating) — ตัวรวมคะแนนทั้งสะพาน (section ท้าย ch.4):**

```
TSR = Σ(ESR × Weight) / Σ(Weight)
```

นี่คือสูตรที่ใกล้เคียง "T-BHI" ที่สุดในเอกสารทั้งสองไฟล์ — weighted average ถ่วงน้ำหนักด้วย component
importance เหมือนแนวทางที่ `bridge_health.py` เดิมตั้งใจทำ (EHI × W แล้วรวม)

## 3. สิ่งที่ยังต้องทำต่อ

1. หาไฟล์ "คู่มือเริ่มต้นโปรเจกต์ประเมินสะพานจากภาพโดรน" ตัวจริง (ที่ [`PROJECT_SUMMARY.md`](../../PROJECT_SUMMARY.md)
   อ้าง section 4.4-4.8) — ยังไม่เจอในโฟลเดอร์นี้
2. ตัดสินใจว่าจะใช้เกณฑ์ไหนเป็นหลักใน `damage_rules.py`: Table 15 (RC/PC-specific, ละเอียดกว่า)
   หรือ DOH Rating ของรายงานรุ่นพี่ (หยาบกว่า, crack width อย่างเดียว) — แนะนำ Table 15
3. พิจารณาเอาสูตร Component Weight / Defect Criticality Weight / TSR มาปรับใช้กับ `element_lookup.py`
   และ `bridge_health.py` แทนของเดิม (ยังไม่เคยดูค่า W เดิมเทียบกัน)
