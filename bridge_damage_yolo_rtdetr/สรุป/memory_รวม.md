## 1. Rule of Tune — คุ้มครองไฟล์ rawdata

กฎเต็มอยู่ที่ `D:\Project AI\rule_of_tune.md` — อ่านไฟล์นั้นก่อนเสมอเวลาจะแตะไฟล์ต้นฉบับ (อาจอัปเดตเพิ่มได้)

**หมายเหตุ path:** กฎพูดถึง `rawdata/` แต่ในโปรเจกต์จริงไม่มีโฟลเดอร์ `rawdata/` — โฟลเดอร์ที่ถูกคุ้มครองจริงคือ `01 Literature Review/` ที่ root ตรงๆ (`02 Methodology & Work/`, `03 Reports/` ยังไม่มี เพราะโปรเจกต์ยังไม่ถึงขั้นนั้น)

**ข้อตกลง 4 ข้อ:**
1. **ห้ามแก้/ทับ/ลบ/ย้ายไฟล์ต้นฉบับ** ใน `01 Literature Review/` และข้อมูลภาคสนามดิบ (เช่น `Bridge/`) โดยไม่ได้รับอนุญาตชัดเจนในบทสนทนานั้น — ไฟล์ที่แก้ได้ปกติ: draft สรุป/note ที่ generate เอง, ไฟล์ .md เอกสารโปรเจกต์ (PROJECT_SUMMARY.md, README, rule_of_tune.md เอง), สคริปต์/config ที่ไม่ใช่ข้อมูลอ้างอิงตรง
2. **ต้องเตือนก่อนเสมอ** (ก่อนขออนุญาต ไม่ใช่หลัง) ว่าไฟล์เป็นแหล่งอ้างอิงต้นฉบับ ถ้าลบ/แก้ผิดอาจหาแทนไม่ได้ — ข้ามขั้นตอนนี้ไม่ได้แม้ผู้ใช้จะสั่งตรงๆ หรือรีบ
3. **Citation integrity** — ห้ามสร้าง/เดาข้อมูลอ้างอิง/ตัวเลข/ผลวิจัยที่ไม่มีจริงในเอกสารต้นฉบับ ต้องตรวจกับไฟล์จริงก่อนอ้างอิงเสมอ ไม่แน่ใจให้บอกตรงๆ ว่ายังไม่ verify
4. **Traceability** — งานเขียนใหม่ควรระบุ path ไฟล์ต้นฉบับที่ใช้ประกอบเสมอ

ลำดับความสำคัญ: กฎ 1 > 2 > 3 > 4 เสมอ

## 2. หลักกันโมเดล Overfit (ตรวจสอบทุกครั้งที่ช่วยเทรน YOLO/RT-DETR)

อธิบายด้วยภาษาง่ายๆ เสมอ (ดูข้อ 3) ไม่ใช้ศัพท์เทคนิคลอยๆ โดยไม่อธิบาย:

1. อย่าเทรนโมเดลจากศูนย์ ใช้โมเดลที่มีคนฝึกไว้แล้วมาต่อยอด (transfer learning)
2. ปรับภาพให้หลากหลาย (หมุน พลิก ปรับมืด/สว่าง) ให้ใกล้เคียงสภาพจริงตอนใช้งาน
3. ความเสียหายแบบไหนภาพน้อยกว่าแบบอื่นมาก ให้เพิ่มภาพแบบนั้นเป็นพิเศษ (oversample rare class)
4. อย่าเชื่อคะแนนตอนฝึกอย่างเดียว ต้องทดสอบกับภาพที่ไม่เคยเห็นมาก่อนจริงๆ (ตัวอย่างเตือนใจ: Chen 2023 val 98%+ แต่ของจริงแค่ 84%)
5. เช็ค recall แยกรายคลาส ไม่ใช่ดูแค่ accuracy รวม (คลาสอันตรายพลาดไม่ได้)
6. ตั้ง early stopping (patience-based) กันเทรนนานเกินจนจำข้อมูลเป๊ะ
7. Severity เป็นระดับ (0-5) ต้องใช้ ordinal-aware loss (ผิดใกล้โทษน้อยกว่าผิดไกล) ความเสียหายซ้อนกันได้หลายแบบต้องใช้ Sigmoid+BCE (multi-label) ไม่ใช่ Softmax บังคับเลือกอย่างเดียว
8. ใช้ foundation model สำเร็จรูป (เช่น SAM) แทนเทรนใหม่หมดถ้าทำได้
9. ทดสอบกับข้อมูลนอก distribution ด้วยถ้าเป็นไปได้ (ไม่ใช่แค่ train/val/test split ปกติ)
10. มี human-in-the-loop เป็น safety net เสมอ ไม่เชื่อ AI 100% โดยเฉพาะจุดวิกฤต

อ้างอิงเปเปอร์: Chen 2023, Lateef & Yu 2026, Çelik et al., CNN systematic review (Sony et al. 2021), สคริปต์เทรนของรุ่นพี่ — รายละเอียดเต็มอยู่ใน `สรุปสาระสำคัญ เกณฑ์.pdf` และ `0_Reading Guide - คำตอบคำถามนำ.pdf` ในโฟลเดอร์นี้

## 6. มุมกล้อง → ลดระดับความมั่นใจ ไม่ใช่แก้ตัวเลขพื้นที่

ตอนคำนวณพื้นที่ pixel → หน่วยจริง (cm²) สำหรับ T-BHI:

**อย่าพยายามแก้พื้นที่ตามมุมกล้องด้วยสูตรเรขาคณิต ให้ใช้มุมกล้องมาลดระดับความมั่นใจของค่านั้นแทน**

- ภาพ DJI ทุกใบมี `drone-dji:GimbalPitchDegree` (+ `GimbalYawDegree`, `GimbalRollDegree`) ฝังอยู่ใน XMP metadata (ยืนยันจริงจากไฟล์ `Bridge/Land/Under/DJI_202510021143_007/DJI_20251002115214_0001_D.JPG` = +3.70°)
- ถ่ายเฉียง = พื้นที่จริงเหลือ pixel น้อยกว่าที่ควร (perspective foreshortening) — ถ้าคำนวณตรงๆ จะได้ค่าต่ำกว่าจริง
- แต่แก้ให้แม่นจริงต้องรู้ทิศทางผิวจริงของแต่ละชิ้นส่วนด้วย (เสาแนวตั้ง vs ท้องสะพานแนวนอน) ซับซ้อนเกินความจำเป็นและเสี่ยงผิดมากกว่าไม่แก้
- **วิธีที่ใช้จริง:** เอามุมกล้องมาเทียบกับมุมที่ควรจะเป็นของชิ้นส่วนนั้น (ตามที่ YOLO-seg บอกว่าเป็นชิ้นส่วนอะไร) แล้วตั้ง **Confidence Flag (High/Medium/Low)** — ใกล้ตั้งฉาก = High, เฉียงพอสมควร = Medium, เฉียงมาก = Low (ให้คนตรวจสอบ ไม่เชื่อตัวเลขเต็มที่) — Confidence Flag นี้มีอยู่แล้วใน Layer 2 ของสูตร T-BHI (ดู `สรุปสาระสำคัญ เกณฑ์.pdf`)

## 7. ใช้เครื่องคนอื่น (เช่นเครื่องอาจารย์) — เช็ค Windows account ก่อนเสมอ

ก่อนเอาข้อมูล private (ภาพโดรน/dataset) เข้าไปเทรนในเครื่องที่ไม่ใช่ของตัวเอง **ต้องเช็คก่อนว่าเครื่องนั้นแยก Windows user account ต่อคนจริงไหม** เพราะ memory/ประวัติ session ของ Claude Code เป็นไฟล์ local ผูกกับ **Windows user profile** (ไม่ใช่บัญชี Claude) — ถ้าทุกคนใช้ Windows account เดียวกัน ใครก็เห็นไฟล์ของกันได้หมด

**วิธีเช็ค (รันใน PowerShell บนเครื่องนั้น):**
```powershell
whoami                  # เช็คว่า login เป็น user ไหนอยู่ตอนนี้
Get-LocalUser            # ดูรายชื่อ user account ทั้งหมดในเครื่อง
Get-ChildItem C:\Users   # ดูว่ามีกี่ profile folder แยกกันจริง
```

**อ่านผล:**
- เห็นหลาย user / หลายโฟลเดอร์ใน `C:\Users` → แยกกันจริง ปลอดภัยกว่า
- เห็น user เดียว/ทุกคนใช้ account เดียวกัน → ข้อมูล/memory เห็นกันได้หมด **ต้องลบข้อมูล private ทุกครั้งหลังใช้เสร็จแน่นอน** (ภาพ/dataset ที่ก๊อปไปเทรน คือสิ่งสำคัญที่สุดที่ต้องลบ — ตัว memory เองไม่ sensitive มาก แค่เป็นโน้ตวิธีทำงาน)
