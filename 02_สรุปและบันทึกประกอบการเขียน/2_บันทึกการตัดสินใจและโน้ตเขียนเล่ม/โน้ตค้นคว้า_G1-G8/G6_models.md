### [29] Structural defect segmentation using a semi-supervised algorithm integrating YOLO and the segment anything model — Kuttuva & Prawin J (2026) — *Automation in Construction* 182, 106709, doi:10.1016/j.autcon.2025.106709 (รับ 4 ธ.ค. 2025, ออนไลน์ 11 ธ.ค. 2025; p.1)
- ชนิด: เปเปอร์วิจัย ; อายุ: 2026 (อยู่ในช่วง 5-10 ปี)
- **วัตถุประสงค์**: แบ่งส่วน (segment) ความเสียหายโครงสร้างระดับพิกเซลโดยใช้เฉพาะป้ายกำกับระดับกรอบ ไม่ต้องใช้ป้ายระดับพิกเซล. "The method requires only object-detection labels, eliminating the need for dedicated segmentation annotations." (p.1)
- **วิธีการ (สถาปัตยกรรม/หลักการ)**: สองขั้น — Stage I: YOLO11 (กรอบแนวนอน HBB) หรือ Oriented YOLO11 (กรอบหมุน OBB) หา region ที่เสียหาย ; Stage II: SAM แบบ zero-shot รับ prompt จากผล Stage I แล้วคืน mask (p.7-8, Fig. 7 p.7). SAM อธิบายตามต้นฉบับ Kirillov: image encoder (ViT-H/L/B) ทำงานครั้งเดียวต่อภาพ, prompt encoder (จุด/กรอบเข้ารหัสด้วย positional embedding; ข้อความผ่าน CLIP; mask ผ่าน conv), mask decoder แบบเบา (p.13-14). มี 2 โหมด: automatic "everything mode" กับ interactive ที่ใช้จุด/กรอบ (p.14).
  - **SAM รับ prompt อย่างไร / ที่เปเปอร์ทดสอบ**: 3 แบบ (p.14) (i) จุด = จุดศูนย์กลางของกรอบที่ YOLO ทำนาย (ii) กรอบ (iii) กรอบ+จุดรวมกัน ; คู่กับ YOLO11 และ Oriented YOLO11 ได้ 6 โมเดลย่อย (p.14-15). "bounding box ... are defined by their corner coordinates" (p.14).
  - **ผลเทียบ prompt (เชิงคุณภาพจากรูป ไม่มีตาราง)**: จุดอย่างเดียว "fail to detect certain cracks" (p.23, ข้อ 1); "the use of the box-based prompt yields improved segmentation performance for both models across all crack datasets compared to other prompt types" (p.23 ข้อ 2); YOLO11+SAM ดีขึ้นเมื่อใช้กรอบ+จุด (p.23 ข้อ 5); ข้อสรุปว่า Oriented YOLO11+SAM + box prompt "most effective" (p.24 และ p.35). **ความไม่สอดคล้องภายใน**: ข้อ 6 (p.23) ว่าดีสุดคือ "combined box-based prompt" แต่ p.24/p.35 สรุปว่า box-based prompt — ใช้ข้อสรุปได้แค่ "box prompt ดีกว่า point-only" อย่าเจาะจงเกินนี้. ตัวเลขทางการ (Table 2, 4) ใช้ box prompt เท่านั้น (p.21).
  - **ไม่ได้อธิบายว่ากรอบหมุน (OBB) ถูกแปลงเป็นกรอบที่ SAM รับอย่างไร** ยืนยันไม่ได้ (SAM ตามคำอธิบายรับกรอบด้วยพิกัดมุม p.14)
- **ชุดข้อมูล** (Table 1, p.8): รอยร้าว 4 ชุด — BPHDR (Roboflow; "Cracks are from the concrete pavement material type", 1,551 ภาพก่อน augment / 4,029 หลัง, ขนาด 344x296 ถึง 416x416), MCDS (790 ภาพ 256x256), BCL_Steel (2,036), BCL_Non-steel (5,769) ; spalling WUTHJ (Roboflow; อาคารและสะพาน; 589 -> 1,767 หลัง augment; 512x512) ; สนิมเหล็ก (corrosion) Virginia Tech Corrosion Condition State Segmentation Dataset (440 -> 1,913; 512x512; 3 ระดับตาม AASHTO/BIRM). ฮาร์ดแวร์เทรน: Intel UHD 770 + AMD Radeon RX 650, RAM 32 GB (p.8). เทรนทุกโมเดล 20 epoch (Table 3, p.17).
- **ตัวเลขผลหลัก (คัดตรงตัว)**:
  - Table 2 (p.15), box prompt, Avg Dice (DS) YOLO11+SAM / Oriented YOLO11+SAM: เทรน BPHDR-ทดสอบ BPHDR **0.6954 / 0.6710** (95% CI [0.638, 0.789] / [0.578, 0.784]; mIoU 0.533 / 0.505) ; เทรน BPHDR-ทดสอบ MCDS **0.3870 / 0.2004** ; BPHDR->BCL_non steel 0.6000 / 0.5715 ; BPHDR->BCL_steel 0.6319 / 0.6463 ; MCDS->BCL_non steel 0.6012 / 0.5468 ; เทรนรวม BHPDR+MCDS+BCL_steel -> ทดสอบ BCL_non steel **0.7951 / 0.6819** (mIoU 0.662 / 0.518). บทสรุปของเปเปอร์เอง: "training and testing on different datasets exhibit poor performance" (p.22 ข้อ 8)
  - Table 4 (p.24), รอยร้าว (สถานการณ์ II-IV): Precision/Recall/mIoU/AUPRC/Dice — YOLO11n-seg 0.759/0.659/0.578/0.709/**0.705** [0.665, 0.766] ; UNet 0.802/0.677/0.505/0.742/**0.735** [0.616, 0.746] ; DeepLabv3+ **0.517** ; Mask R-CNN **0.621** ; SegFormer 0.723/0.762/0.589/0.743/**0.742** [0.718, 0.864] ; YOLO11+SAM 0.854/0.703/0.601/0.779/**0.771** [0.734, 0.828] ; Oriented YOLO11+SAM 0.893/0.759/0.690/0.826/**0.820** [0.793, 0.867].   - Table 5 spalling (p.31): YOLO11n-seg Dice **0.793** [0.66, 0.85], recall 0.912 ; UNet 0.735 ; DeepLabv3+ 0.771 ; Mask R-CNN 0.756 ; SegFormer 0.808 [0.652, 0.873] ; YOLO11+SAM **0.803** [0.652, 0.87] (P 0.848, R 0.833, mIoU 0.693).
  - Table 6 corrosion เหล็ก (p.31): YOLO11n-seg Dice **0.617** ; UNet 0.571 ; DeepLabv3+ 0.592 ; Mask R-CNN 0.519 ; SegFormer **0.631** ; YOLO11+SAM **0.606** [0.519, 0.713] (P 0.702, R 0.534).
  - Dice นิยามในเปเปอร์ = 2PR/(P+R) (Eq.3, p.20) คือ F1 ระดับพิกเซลจาก P และ R รวม ไม่ใช่ Dice ต่อภาพ — อธิบายว่าทำไมตัวเลข Table 4 (Dice 0.771/0.820) สูงกว่า Table 2 ในสถานการณ์ II-IV มาก (0.20-0.65) ; **เปเปอร์ไม่อธิบายความต่างนี้** (ข้อสันนิษฐานเป็นของผู้อ่านนี้ ยืนยันไม่ได้). เทียบตัวเลขในนามธรรม: abstract บอก "average Dice score of 0.7" (p.1)
  - ความเร็ว (Table 8, p.35): เวลา/epoch YOLOv11-seg 95 s, YOLO11-SAM 120 s ; inference ต่อภาพ YOLO-seg 95 ms, YOLO11-SAM 120 ms, UNet 265 ms, Mask R-CNN 460 ms (ตัวเลข 95/95 และ 120/120 ซ้ำกันทั้งหน่วย s และ ms — น่าสงสัย ตรวจต้นฉบับ) ; พารามิเตอร์ SAM 110 M + YOLO11n 2.9 M (Table 3, p.17).
- **รอยร้าวบางคดโค้ง/กรอบ vs mask (ตอบคำถามโดยตรง)**:
  - เปเปอร์ **ไม่ได้วัดตัวเลข** "พื้นที่จากกรอบ เทียบ พื้นที่จาก mask". หลักฐานที่มีเป็นเชิงคุณภาพ: HBB "often encompass a significant portion of the background in the box in case of rotated or irregularly shaped objects" (p.11) ; "HBB ... tends to include a substantial amount of background within the bounding boxes" (p.21 ข้อ 1) ; กรอบหมุนจับรอยร้าวเอียงได้ดีกว่า HBB (p.21-22 ข้อ 2-5, Fig.5 p.6/13) และ OBB "ให้ทิศทางและความยาว" (p.13) -> เป็นเหตุผลสนับสนุนว่ากรอบแนวนอนให้พื้นที่เกินจริงกับรอยเอียง แต่**ไม่มีค่าเกินกี่ %**
  - **SAM เองก็ไม่สมบูรณ์กับรอยบาง**: "very fine or thin cracks may consist of too few pixels for reliable detection by YOLO11 and for precise mask generation by SAM. Since SAM produces smooth masks from region-level prompts, it may not accurately delineate intricate boundaries in cases of extremely thin cracks" (p.26) ; "SAM generates smooth region-level masks, which may not capture the intricate boundaries of alligator cracks" (p.24) ; หน้า 22 ข้อ 5: รอยร้าวแบบไม่เป็นระเบียบ/alligator บางภาพ mask "deviate significantly from the ground truth" (Fig.9a, 9d) ; หน้า 22 ข้อ 6: รอยที่มีคราบ/ลายมือ/ขอบคล้ายรอย ทั้งสองโมเดล "struggle" ; p.24 ข้อ 1: UNet และ SegFormer "perform better" กับรอยหลายแบบ ; Table 7 (p.34): YOLO11-SAM "Difficulty in thin cracks with a different texture and a complex background"
  - ผลต่อเหตุผลที่เราเลือก SAM: **สนับสนุนได้** (1) mask จาก SAM ไม่รวมพื้นหลังเท่ากรอบ (เชิงคุณภาพ) (2) ไม่ต้องมีป้ายพิกเซล — เปเปอร์อ้างลดเวลาป้ายกำกับ "~15x" และต้นทุน "~30x" (p.6) **แต่ไม่มีการวัดรองรับในข้อความที่เหลือ** (พบเลขนี้ที่เดียว) อย่าอ้างตัวเลขนี้เป็นผลวิจัย (3) box prompt ดีกว่า point-only ตรงกับแผนเราที่ให้ VLM ส่งกรอบ. **ข้อควรระวัง**: เปเปอร์ไม่ได้แสดงว่า SAM ชนะ YOLO-seg ที่เทรนด้วยป้ายพิกเซล — spalling YOLO11n-seg 0.793 ≈ YOLO11+SAM 0.803 (CI ซ้อนกัน) และ corrosion YOLO11n-seg 0.617 > 0.606 ; ข้อได้เปรียบของ SAM ในเปเปอร์คือ "ไม่ต้องป้ายพิกเซล" ไม่ใช่ความแม่นกว่า
- **เวอร์ชัน SAM**: ข้อความอธิบาย SAM ตาม Kirillov [33] (ViT-H/L/B, p.13-14) แต่ legend รูป Fig.18-19 เขียน "YOLO11 and SAM2 / Oriented YOLO11-SAM2" (p.20, p.22) และบทสรุปเขียน "SAM2-based zero-shot segmentation model" (p.35) ; ไม่ระบุ checkpoint/ขนาด และไม่มีคำว่า SAM 3 ->**เวอร์ชันที่ใช้จริงในเปเปอร์ยืนยันไม่ได้ (SAM หรือ SAM2)**. เปเปอร์เรียก SAM ว่า "unsupervised segmentation model" (p.13) ซึ่งเป็นการใช้คำที่หลวม — ใช้คำว่า zero-shot / promptable
- **ใช้กับงานโยธาหรือไม่**: ภาพรวม "civil infrastructure" แต่ชุดข้อมูลจริง = รอยร้าวผิวถนนคอนกรีต (BPHDR), เหล็ก/ไม่ใช่เหล็ก (BCL), spalling อาคาร+สะพาน (WUTHJ), สนิมเหล็ก (VT). **ไม่ใช่ภาพโดรน ไม่ใช่คาน PC I-girder ไม่ใช่ภาพใต้สะพาน**. Intro กล่าวถึง UAV กว้างๆ (p.1) แต่ไม่มีการทดลองโดรน. "limited to single-defect segmentation models" (p.7) = ไม่ได้ทดสอบหลายคลาสพร้อมกัน ; เปเปอร์ระบุ future work "multi-class defect segmentation" และ "quantifying damage by pixel-based metrics" (p.35) -> **ไม่ได้วัดขนาดจริง**
- **ความเกี่ยวข้องกับงานเรา**: **ใช้แน่ (หลัก)** — เป็นเปเปอร์เดียวในกลุ่มที่ทำ "detector -> SAM mask" กับความเสียหายโครงสร้าง โดยตรงตรรกะ 3.5 ข้อ 4 (เราใช้ Qwen แทน YOLO เป็นตัวให้กรอบ) ; รองรับ 2.3 (เหตุผลที่ใช้ SAM, ข้อจำกัด thin crack, จุดเทียบ YOLO-seg/UNet/SegFormer/Mask R-CNN)
- **ข้อเท็จจริงที่หยิบไปเขียนได้เลย**: (1) กรอบ detector เป็น prompt ให้ SAM แล้วได้ mask โดยไม่ต้องมีป้าย mask (p.1, p.7-8) (2) 3 รูปแบบ prompt และกรอบดีกว่าจุดเดี่ยว (p.23) (3) Table 4-6 เทียบกับ 5 โมเดลที่เทรนด้วยป้ายพิกเซล (pp.24, 31) (4) ข้อจำกัด thin/alligator crack (p.24, p.26) (5) สามชนิดความเสียหายที่ทดสอบ: รอยร้าว spalling (รวมที่เห็นเหล็กเสริม) corrosion (p.35)
- **ข้อจำกัด/ห้ามอ้างเกิน**: ไม่ใช่โดยตรงกับโดรน/คาน PC ; spalling-with-exposed-rebar ไม่ใช่คลาสแยก (ปนอยู่ใน WUTHJ, Table 1 p.8) ; ไม่มี efflorescence/honeycomb ; corrosion = โลหะ ไม่ใช่คราบสนิมบนคอนกรีต ; ตั้งชื่อชุดข้อมูลไม่คงที่ (BPHDR/BHPDR) ; คำอธิบายสถาปัตยกรรม YOLO11 ในเปเปอร์ (CSPDarknet53, anchor-based, objectness head, p.9, p.15) ไม่ได้อธิบาย segmentation head ของ YOLO11-seg เลย และยืนยันไม่ได้ภายในกลุ่มนี้ — ก่อนคัดลอกคำอธิบาย YOLO ให้ไปตรวจแหล่งปฐมภูมิ ; ตัวเลข Table 4 กับ Table 2 สอดคล้องกันไม่ได้โดยไม่มีคำอธิบาย (ดูข้างบน)

### [28] Plug-and-play method for segmenting concrete bridge cracks using the segment anything model with a fractal dimension matrix prompt — Teng, Liu, Situ, Chen, Wu, Zhang, Wang (2025) — *Automation in Construction* 170, 105906, doi:10.1016/j.autcon.2024.105906
- ชนิด: เปเปอร์วิจัย ; อายุ: 2025 (รับ 22 ก.ค. 2024; ออนไลน์ 4 ธ.ค. 2024; p.1)
- **วัตถุประสงค์**: แบ่งส่วนรอยร้าวคอนกรีตสะพาน (บนบกและใต้น้ำ) โดยใช้ SAM แบบไม่ต้องเทรน ป้อน prompt เป็น "fractal dimension matrix" (p.1)

(p.10) ; ภาพมือถือ 379 ภาพที่ 50-70 ซม. -> ตัด 256x256 ได้ 1,463 ภาพ + SDNET2018 3,006 ภาพ = 4,469 ภาพ (train 3,575 / test 894; p.10)
- **ตัวเลข (คัดตรงตัว)**: "the mAP reached 92%" (p.11) — แต่ abstract/บทสรุปเรียกว่า "accuracy of 92%" (p.1, p.15) ซึ่งเป็นการใช้คำคลาดเคลื่อน ; Table 6 (morphological + planar marker, 0.216 mm/px, p.14): รอยจริง 0.350/0.650/0.700/0.650/0.350 mm วัดได้ 0.432/0.648/0.648/0.648/0.216 mm คลาดเคลื่อนสัมบูรณ์ 0.082/0.002/0.052/0.002/0.134 mm (ร้อยละ 23.43/0.31/7.43/0.31/38.29) ; Canny รอย 3 ผิดเป็น 38.29% (Table 7, p.15) ; total station + morphological คลาดเคลื่อน 0.013-0.129 mm (Table 8, p.15). บทสรุป: "overall crack measurement accuracy was superior to 0.22 mm" (p.15) ; ผลต่างระหว่างสองวิธี scale 0.005 mm (p.15)
- **ข้อสังเกต/ข้อจำกัด**: (1) ตัวเลข "0.22 mm" เท่ากับขนาดพิกเซลที่ 0.216-0.221 mm/px พอดี — 1 พิกเซลคือหน่วยย่อยที่สุดของการวัด รอยกว้าง 0.35 mm ได้ 1-2 พิกเซล ทำให้เกิด error 23-38% ในรอยบาง ; (2) **ตรวจสอบกับรอยจริงเพียง 5 รอย** ; (3) ขั้นแบ่งส่วนรอยเป็นแค่ threshold+edge ภายในกรอบ ไม่ใช่โมเดลแบ่งส่วน และ"กรอบ 3 กรอบต่อรอย" มาจากวิธีป้ายกำกับ (p.12) ; (4) วัดแบบ pixel-only ต้องการรอยตั้งฉาก (align vertically, p.9) ; (5) ไม่ได้ใช้เลเซอร์ — ทบทวนว่างานเลเซอร์คืออะไร: Park et al. (YOLOv3 + structured light) ความกว้างบางสุด 0.91 mm ; Kim et al. 2018 (R-CNN + planar marker) 0.53 mm ; Kim & Cho 2019 (Mask R-CNN) รอย >0.3 mm error <0.1 mm (p.3) ; ผู้เขียนอ้างว่าเลเซอร์บนโดรน "requires additional system calibration" (p.3) ; มีอ้างอิง Kao et al. 2022 "Bridge Crack Inspection Efficiency of an UAV System with a Laser Ranging Module" *Sensors* 22, 4469 ([33], p.17) เป็นแนวทางต่อ (**ไม่ได้อ่านฉบับนั้น**) ; (6) ชุดโมเดลนี้ตรวจแค่ crack ไม่มีคลาสอื่น
- **ใช้กับงานโยธา**: ใช่โดยตรง (สะพานจริงในไต้หวัน: Xihu River, Houlongguanhai, Touwu; p.10) + โดรนจริง
- **ความเกี่ยวข้องกับงานเรา**: **ใช้เสริม** — ใกล้ 2.3 เฉพาะตรงที่เป็น "ตัวตรวจจับระดับกรอบ + โดรน + สะพาน" ; **คุ้มค่ามากกว่าที่ชื่อบอกสำหรับ 2.5/3.6** (วิธี scale จากมาตรฐานในภาพเทียบ GSD, ตัวเลข error จริง, ข้อจำกัด 1 พิกเซล) ; **ไม่ใช่หลักฐานสำหรับ YOLO-seg หรือ SAM**
- **ประเมิน YOLOv4 "ควรอ้างเป็นพื้นฐานหรือหาตัวแทน"**: เปเปอร์ที่มีให้เป็นงานปี 2023 ที่ใช้ YOLOv4 เป็น detector เท่านั้น (ไม่แบ่งส่วน) ; ไม่ควรใช้เป็นหลักฐานของ "YOLO-seg" ; ไม่ควรอ้างเป็นรุ่นพื้นฐานของ pipeline (เราใช้ YOLO-seg ใหม่กว่า) ; **ควรเก็บไว้เป็นงานอ้างอิงของ "UAV + detector + วัดรอยร้าว" ในบท 2.3/2.5/2.6** และถ้าต้องอธิบายสถาปัตยกรรม YOLO ให้ใช้เปเปอร์ต้นฉบับ YOLOv4 [43] หรือเปเปอร์ YOLO-seg รุ่นล่าสุดที่ต้องหามาแยก (ไม่มีในกลุ่มนี้)

## สรุปกลุ่ม

- **ควรเข้า proposal**: **[29] (หลักของ 3.5 ข้อ 4 และ 2.3)** ; **[28] (เสริม: SAM ต้องมี prompt ที่ดี, ได้ผลบนรอยร้าวสะพาน)** ; **[30] (เสริม 2.3/2.5/2.6: โดรน+สะพาน+วัดความกว้าง — แต่เปลี่ยนบทบาทจาก "YOLOv4 พื้นฐาน" เป็น "งานที่เกี่ยวข้อง")** ; **[26] (เสริม: ชุด 5 คลาสใกล้ของเรา, recall ของคลาสยาก, ตัวอย่างตัวตรวจจับ DETR บนสะพาน; ใช้เป็นเหตุผลว่าทำไมกรอบอย่างเดียวไม่พอ)**.
- **ตัดหรือใช้น้อย**: **[27]** (ไม่ใช่ RT-DETR ต้นฉบับ, ข้อมูลสังเคราะห์, F1 ผิด, ใต้น้ำ) — เก็บไว้เป็นตัวอย่างประกอบเท่านั้น ถ้าไม่จำเป็นตัด.
- **ช่องว่างหลักฐาน (กลุ่มนี้ยังไม่มี)**:
  1. **YOLO-seg/instance segmentation สำหรับ "จำแนกชิ้นส่วนสะพาน"** — ไม่มีฉบับไหนทำ component segmentation (ทั้ง 5 ฉบับเป็นความเสียหาย) ; YOLO-seg ปรากฏเป็นแค่ baseline YOLO11n-seg (Dice 0.705 รอยร้าว, 0.793 spalling, 0.617 corrosion; Table 4-6 pp.24, 31) และ LCA-YOLOv8-Seg แบบอ้างทอด (27 p.2) ; ไม่มีคำอธิบาย mask head ของ YOLO-seg ; ต้องหาเปเปอร์ที่ใช้ YOLO-seg/instance segmentation แบ่งส่วนชิ้นส่วนสะพานหรืออาคารโยธา (และแหล่งปฐมภูมิของ YOLO-seg) แยก
  2. **VLM/Qwen -> SAM** — ไม่มีฉบับไหนใช้ VLM ให้กรอบแก่ SAM ; มีแต่ detector -> SAM ([29]) ; ต้องใช้กลุ่มเปเปอร์ VLM (ไฟล์ 23-25, 36-38) มารองรับครึ่งหน้า
  3. **SAM 3** ไม่มีหลักฐานเลย ; SAM2 โผล่ใน [29] เป็นแค่ legend/บทสรุป (p.20, 22, 35) โดยไม่มีรายละเอียด ; ต้องหาแหล่งปฐมภูมิของรุ่นที่เลือกใช้
  4. **SAM บน crack โค้งบางจริง แบบเทียบกรอบ vs mask เป็นตัวเลข** — ไม่มีฉบับไหนวัดพื้นที่เกินจริงของกรอบ ; มีแค่ข้อความเชิงคุณภาพ (29 pp.11, 21) และตัวเลข error ของวิธีกรอบ (26 Table 13) ; ถ้าจะใช้เหตุผล "กรอบให้พื้นที่เกิน" ต้องวัดเองในงานเรา (เป็นผลของ 3.5/3.6 ไม่ใช่ผลวรรณกรรม)
  5. **หลายคลาสพร้อมกัน + Efflorescence/Honeycomb/Exposed rebar เป็นคลาสแยกใน segmentation** — [29] ทดสอบทีละคลาส (p.7) ; [26] มี 5 คลาสแต่เป็น detection
  6. **ภาพโดรนใต้สะพาน/คาน PC I-girder** ไม่มีฉบับไหนทำ (ชุดข้อมูลสาธารณะเป็นหลัก ยกเว้น [30] ที่ถ่ายโดรนที่ระยะ 1 ม. ในชุดทดสอบ)
- **ข้อควรระวังต่อแผนเรา**: [29] ไม่ได้พิสูจน์ว่า "YOLO+SAM แม่นกว่า YOLO-seg" แต่พิสูจน์ว่า "ได้ระดับใกล้เคียงโดยไม่ต้องป้ายพิกเซล" (CI ซ้อนกัน; spalling/corrosion YOLO11n-seg ไม่แพ้) ; ข้ออ้างลดเวลา 15x/ต้นทุน 30x ของ [29] (p.6) ไม่มีหลักฐานรองรับในไฟล์ — อย่าใช้ ; ทุก Dice/IoU ในกลุ่มนี้มาจากชุดข้อมูลสาธารณะที่ไม่ใช่โดรน — ห้ามอ้างเป็นประสิทธิภาพคาดการณ์ของงานเรา.
