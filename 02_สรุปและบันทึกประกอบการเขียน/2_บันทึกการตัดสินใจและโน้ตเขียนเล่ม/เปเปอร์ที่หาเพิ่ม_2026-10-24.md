- **ที่อ้างไม่ได้:** (ก) หัว segmentation อธิบายแค่ "lightweight mask branches coupled to shared features" (p.4) ไม่มีรายละเอียดวิธีสร้าง mask ; (ข) ตาราง 2 มีเฉพาะ YOLO26 **ไม่มีผล segmentation เทียบกับ YOLO11** ในหน้าที่อ่าน → ห้ามเขียนว่า YOLO26-seg ดีกว่า YOLO11-seg ; (ค) ข้อความว่า STAL ช่วยกับภาพโดรน (p.7) และว่าคงความแม่นเมื่อ quantize INT8 (p.10) **ไม่มีตารางตัวเลขรองรับ** ในหน้า 1–12 ; (ง) ตัวเลขใน Figure 3 (แผนผังสถาปัตยกรรม) อ่านแล้วไม่สมเหตุสมผลหลายจุด อย่าคัดรูปไปใช้ ; (จ) ผลเป็น COCO ทั้งหมด ไม่มีสะพาน/โดรน/รอยร้าว ; (ฉ) สถานะการตีพิมพ์ยืนยันไม่ได้ (เห็นเป็น arXiv v5)
- ข้อสังเกตของฉัน: งานเราประมวลผลออฟไลน์ ข้อดีหลักของ YOLO26 คือความเร็วบนอุปกรณ์ขอบ (edge) ซึ่งไม่ใช่เหตุผลเลือกของเรา — ถ้าเลือก YOLO26 ต้องหาเหตุผลอื่นรองรับ (เช่น รุ่นล่าสุดของ Ultralytics ที่ใช้ได้จริง) และควรเก็บ YOLO11 ไว้เป็นรุ่นเทียบถ้ามีเวลา

## ช. SAM 3 (มะขามเพิ่มไฟล์ `งานใหม่\paper mk\sam3.pdf`) — อ่านแล้ว

Carion, Gustafson, Hu, et al. (2026). *SAM 3: Segment Anything with Concepts*. **ICLR 2026** (หน้าแรกของไฟล์มะขามเขียน "Published as a conference paper at ICLR 2026"; ฉบับ arXiv:2511.16719v2 28 มี.ค. 2026)
- **วิธีอ่าน:** ไฟล์มะขามเป็นภาพสแกน (78 หน้า ไม่มีชั้นข้อความ) — ฉันอ่านเนื้อหาจากสำเนา arXiv v2 ที่โหลดไว้ (ข้อความอ่านได้) และเปิดหน้า 1 กับหน้า 18 ของไฟล์มะขามเทียบ เนื้อหาตรงกัน **แต่เลขหัวข้อภาคผนวกต่างกัน** (ฉบับ ICLR: Limitations = ภาคผนวก C หน้า 18 ; arXiv v2 = ภาคผนวก B) → ตอนอ้างหน้า/หัวข้อ ให้ใช้เลขจากไฟล์ ICLR ของมะขาม และตรวจตัวเลขในไฟล์นั้นอีกครั้ง (ข้อมูลจากข้อ 2–6 ด้านล่างมาจากสำเนา arXiv ยังไม่ได้เทียบทีละหน้า)
- ข้อมูลที่ยืนยันจากเนื้อหา:
  1. Prompt: **concept prompt** = วลีคำนามสั้นๆ และ/หรือภาพตัวอย่าง (กรอบบวก/ลบ) ; **visual prompt** = จุด กรอบ มาสก์ (แบบ SAM 2) (§3)
  2. ข้อความจำกัดเป็น "simple noun phrase" ; "not designed for long referring expressions" — ใช้ร่วมกับ MLLM ได้ (**SAM 3 Agent**: MLLM เสนอวลีคำนาม ให้ SAM 3 ส่งมาสก์กลับ แล้ววนจนพอใจ ; ทดสอบ zero-shot บน ReasonSeg/OmniLabel/RefCOCO+/RefCOCOg ไม่ใช่งานโยธา)
  3. ขนาด ~850M พารามิเตอร์ (~450M vision, ~300M text, ~100M detector+tracker) ; ภาพเดียว 100+ วัตถุ 30 ms บน H200 (ไม่ใช่การ์ดทั่วไป)
  4. **Limitations (หน้า 18 ฉบับ ICLR):** "struggles to generalize to fine-grained out-of-domain concepts ... in a zero-shot manner, especially in niche visual domains (e.g., thermal imagery)" ; ปรับตัวได้ด้วยการ fine-tune บนข้อมูลคนติดป้ายปริมาณน้อย
  5. **การ fine-tune ในเปเปอร์ = "fine-tune SAM 3 without mask loss" วัด bbox mAP** บน ODinW13/RF100-VL แบบ 10-shot (Tab. 2) → **เปเปอร์นี้ไม่ได้ทดสอบ fine-tune เพื่อ mask** ; หลักฐาน fine-tune mask อยู่ที่พรีพรินต์ SAM3-LoRA (ข้อมูลอุโมงค์/S2DS)
  6. SAM 3 ไม่มีข้อมูลหรือการทดสอบเรื่องสะพาน คอนกรีต รอยร้าว (ค้น crack/aerial แล้ว พบ "aerial" เฉพาะในรายชื่อชุดข้อมูล/หมวดภาพ)
- **ความหมายต่อ pipeline ของเรา (ข้อสังเกตของฉัน):** SAM 3 รับข้อความ "crack" แล้วหาทุกอินสแตนซ์เองได้ จึงมี 2 รูปแบบให้เลือก (ก) Qwen ให้กรอบ → ส่งให้ SAM 3 เป็นกรอบ/ภาพตัวอย่าง (แบบที่เราวางไว้) (ข) ใช้ SAM 3 รับข้อความตรงๆ และใช้ Qwen เป็นผู้ตรวจ/คัดกรอง (แนวเดียวกับ SAM 3 Agent) — การเลือกระหว่างสองแบบต้องตัดสินใจ และต้องบอกเหตุผลใน 3.5.3 ; ศัพท์อย่าง efflorescence/spalling/honeycomb น่าจะ "fine-grained out-of-domain" ตามนิยามของ Limitation ข้อ 4 (ข้อนี้เป็นข้อสันนิษฐานของฉัน ไม่ใช่ผลทดสอบในเปเปอร์)

## ฌ. YOLO26 ฉบับทางการของ Ultralytics (จากผลค้น Google Scholar ของมะขาม ข้อ 5) — โหลดและอ่านแล้ว

**แก้ข้อความก่อนหน้า:** ที่ฉันเขียนว่า YOLO26 ไม่มีเปเปอร์ต้นฉบับของ Ultralytics นั้นไม่ถูกแล้ว — มี: Jocher, Qiu, Liu, Lyu, Akyon, Kalfaoglu (2026). *Ultralytics YOLO26: Unified Real-Time End-to-End Vision Models*. arXiv:2606.03748 (ส่ง 2 มิ.ย. 2026) ไฟล์: `เปเปอร์โหลดเพิ่ม_2026-10-24\14_Ultralytics-YOLO26_Jocher2026_arXiv2606.03748.pdf` (31 หน้า) — **ตัวนี้ควรเป็นอ้างอิงหลักของ YOLO26 แทน Sapkota 2509.25164** (YOLOv8/YOLO11 ยังไม่มีเปเปอร์ต้นฉบับ)
- เนื้อหาที่อ่านแล้ว: ตัด DFL, หัวคู่แบบ NMS-free, MuSGD + Progressive Loss + STAL ; **ส่วน instance segmentation (§3.4.1):** ยังใช้ prototype + coefficient (mask = Σ c_k·P_k, สมการ 7) เพิ่ม **multi-scale proto module** (รวมฟีเจอร์ทุกระดับก่อนสร้าง prototype) และ **ตัวสอนเสริมแบบ semantic segmentation เฉพาะตอนฝึก** (BCE+Dice, ถูกถอดตอนใช้งาน)
- ผล: ทุกขนาด YOLO26 ดีกว่า YOLO11 +1.6 ถึง +2.5 box AP และ **+2.4 ถึง +3.7 mask AP บน COCO instance segmentation** (§4.5.1; ตารางเต็มอยู่ในภาคผนวก S5/ตาราง S9 ซึ่งฉันยังไม่ได้อ่าน) ; ablation บน YOLO11s-seg (ตาราง 8): mask mAP 32.0 → 32.4 (+multi-scale proto) → 32.7 (+auxiliary loss) = ส่วนที่มาจากการแก้เฉพาะ segmentation เพียง +0.7 (ที่เหลือมาจากการปรับตัวตรวจจับและวิธีฝึก — ข้อสังเกตของฉัน)
- **อ่านภาคผนวกแล้ว (ตาราง S9 — COCO val, 640 px, mask AP: YOLO11-seg → YOLO26-seg [E2E / Non-E2E]):** n 32.0 → 33.9 / 34.4 · s 37.8 → 40.0 / 40.5 · m 41.5 → 44.1 / 44.4 · l 42.9 → 45.5 / 46.0 · x 43.8 → 47.0 / 47.5. **ตัวเลข "+2.4 ถึง +3.7" ในเนื้อความเป็นของเส้นทาง Non-E2E (ใช้ NMS)**; เส้นทาง E2E (ไม่ใช้ NMS) ได้ **+1.9 ถึง +3.2** — ต้องบอกว่าอ้างเส้นทางไหน ; ความเร็ว: YOLO26-seg ไม่ได้เร็วกว่า YOLO11-seg ทุกขนาด (ตัวอย่าง s: T4 3.3 vs 2.9 ms, พารามิเตอร์ 10.4M vs 10.1M ; n เร็วกว่าบน CPU 53.5 vs 65.9 ms แต่ช้ากว่าบน T4 2.1 vs 1.8) ; ความหน่วงของ Non-E2E ไม่รวมเวลา NMS
- **ข้อควรระวัง:** (ก) เป็น arXiv โดยผู้พัฒนาเอง (ตัวเลข COCO ผู้พัฒนารายงานเอง ยืนยันการทบทวนไม่ได้) ; (ข) YOLO26 ฝึกจากน้ำหนัก Objects365-v1 (150 epoch) แล้ว fine-tune บน COCO (§4.1, S3) — **เปเปอร์ไม่ได้บอก (เท่าที่อ่านพบ) ว่า YOLO11 ที่นำมาเทียบใช้การฝึกเริ่มต้นแบบเดียวกันหรือไม่** ความต่างจึงอาจรวมผลของการ pretrain ด้วย ; (ค) ไม่มีสะพาน รอยร้าว หรือโดรน ; (ง) ใบอนุญาต: ผลค้นระบุ AGPL-3.0 และ Enterprise ตามเอกสาร Ultralytics (ยังไม่ได้ตรวจต้นฉบับ) — ตรวจเงื่อนไขก่อนใช้จริง

**ข้อจำกัดของเปเปอร์ (ของฉัน):** ข้อความล้วน ไม่ใช่ VLM ไม่มีภาพ ไม่มี bbox ไม่เกี่ยวกับสะพาน/คอนกรีต/รอยร้าว ; โมเดลเป็น Qwen-7b รุ่นแรก (ไม่ใช่ Qwen3-VL/Qwen3.6) ; ตัวชี้วัดคือคะแนนจาก GPT-4o ซึ่งเป็นผู้ตัดสินอัตวิสัย ไม่ใช่ความถูกต้องของค่า ; ไม่ระบุ hyperparameter fine-tune ในหน้าที่อ่าน ; test เพียง 23 เคส ไม่รายงานค่าทางสถิติ ; เรียกตัวเองว่า "preliminary exploration" (หน้า 14)

**ใช้กับโครงงานได้แค่ไหน — ตัดสินแล้ว: "อาจใช้" ระดับอ่อน**
- ใช้ได้ **ประโยคเดียวใน 2.x / 3.5.3** ว่ามีงานวิศวกรรมที่ fine-tune Qwen ด้วยข้อมูลเฉพาะทางจำนวนน้อย (127 รายงาน) แล้วผลดีขึ้นในบางด้าน ด้วย PEFT — เป็นหลักฐาน "ทำได้ในเชิงหลักการ" เท่านั้น ห้ามอ้างว่าสนับสนุนการ fine-tune VLM ตรวจรอยร้าว
- ใช้เป็นเหตุผล **ทำไมเราไม่ให้ Qwen ตอบตัวเลข**: เปเปอร์เองแสดงว่า Qwen ที่ fine-tune แล้วยังแต่งตัวเลขผิด เราจึงให้ Qwen ทำแค่ "ระบุตำแหน่ง+ชนิด" แล้วให้ SAM 3 วัดพื้นที่เอง (ใช้คู่กับ hallucination survey Chen 2025 ไฟล์ 07 ซึ่งตรงกว่า)
- **ไม่ควรใช้** เป็นเปเปอร์หลักของ 2.x ส่วน VLM: ข้อความล้วน + Qwen-7b เก่า + ตัวชี้วัดเป็นคะแนน GPT — กรรมการอ่านแล้วจะถามว่าเกี่ยวกับภาพโดรนตรงไหน
- ถ้าต้องตัดเพื่อประหยัดพื้นที่ → ตัดได้ ไม่เสียอะไร (ไฟล์ 03 Qwen2.5-VL และ 04 Qwen3-VL ตรงกว่ามาก)

## ฏ. 2llm.pdf = DamageQwen (มะขามโหลดเอง 24 ต.ค. — อ่านหน้า 1–12 จาก 13; หน้า 13 = รายการอ้างอิง ยังไม่ได้เปิด)

**ตัวเปเปอร์:** Zhang & Liu (2025) *Vision-enhanced multi-modal learning framework for non-destructive pavement damage detection*. Automation in Construction 177, 106389. DOI 10.1016/j.autcon.2025.106389 (City University of Hong Kong; open access CC BY-NC) — ไฟล์เป็นภาพสแกน อ่านจากภาพ

**โครงสร้าง (หน้า 3–6, Fig. 1–4):** YOLO v11x ตรวจกรอบ+ชนิดความเสียหาย (ภาพย่อ 224×224) → CLIP กรองกรอบซ้ำ (cosine > 0.95) และยืนยันชนิด → สร้าง prompt ข้อความ "transverse crack located in [x1,y1,x2,y2]…" + "Describe this image." → **Qwen2-VL-7B-Instruct-GPTQ-Int8 รับภาพเต็ม + prompt นี้ แล้วเขียนคำบรรยาย** (ตำแหน่ง ขนาดเป็นพิกเซล ความรุนแรง คำแนะนำซ่อม)

**ตอบ 3 ข้อที่ค้างไว้ (ตอบจากตัวเปเปอร์):**
1. Qwen **ไม่ได้ให้พิกัดกรอบ** — กรอบมาจาก YOLO แล้วป้อนให้ Qwen เป็นข้อความ ผู้เขียนเขียนเองว่า VLM ทั่วไป "lack precision in locating specific small defects like cracks" (หน้า 3) และ YOLO ตรวจเฉพาะที่ detector เก่งกว่า VLM (หน้า 2)
2. ตัวชี้วัดฝั่ง Qwen เป็น **ROUGE / BLEU / METEOR / BERTScore** (คุณภาพข้อความเทียบคำบรรยายที่ผู้เชี่ยวชาญเขียน 285 ตัวอย่าง) ไม่มี mAP/IoU ของ Qwen เลย; ตัวเลข mAP มีเฉพาะ YOLO บน RDD2022: **YOLO11x mAP50 0.5183, mAP50–95 0.2600, P 0.6078, R 0.5105** (Table 2)
3. **ไม่ได้ fine-tune Qwen** — หน้า 6–7: "The model parameters remain frozen, description accuracy is only enhanced by in-context examples" (few-shot 1/2/4 ตัวอย่างใน prompt) ทั้งที่หน้า 3 ข้อ 4 ใช้คำว่า "fine-tunes the output with minimal examples" → **ในเปเปอร์ขัดกันเอง ให้ถือตามหน้า 6–7 (frozen)** ห้ามอ้างว่าเปเปอร์นี้ fine-tune Qwen

**ผลหลัก:** Table 3/4 DamageQwen ชนะ Qwen2-VL-7B ดิบและ Llama-3.2-11B-Vision ในเกือบทุก metric ข้อความ (เช่น 4-shot, prompt 2: ROUGE-1 0.4828 vs 0.4378/0.4372) ; ablation Table 6: ROUGE-1 0.3055 → 0.3312 (+YOLO) → 0.3354 (+CLIP) — ส่วนต่างจาก CLIP เล็กมาก (ผู้เขียนยอมรับหน้า 10) ; ผลบน crack จริงเป็น **ตัวอย่างเชิงคุณภาพ 1 ภาพ** (Fig. 9–10)

**ข้อจำกัด (ส่วนใหญ่ผู้เขียนยอมรับเองหน้า 11–12):** ไม่มีตัวชี้วัดเชิงปริมาณของความกว้าง/ความยาวรอยร้าว — ผู้เขียนเขียนเองว่าตัวเลขพิกเซลของ DamageQwen ใน Fig. 9 "is wrong" ; ผิวถนนไม่ใช่สะพานคอนกรีต ; ไม่ใช่ภาพโดรน ; ทดสอบแค่ 4 ชนิด (transverse/longitudinal/alligator/pothole) ; ภาพ YOLO ถูกย่อ 224×224 ; ข้อมูลเฉลย "available on request" ; metric ข้อความวัดความคล้ายถ้อยคำ ไม่ใช่ความถูกต้องของข้อเท็จจริง

**ใช้กับโครงงาน — ตัดสินแล้ว: "ใช้ได้" แต่เป็นหลักฐานที่ชี้ข้อควรระวังของ 3.5.3 ไม่ใช่หลักฐานสนับสนุนตรงๆ**
- ✅ ใช้ใน 2.x เป็นงานก่อนหน้าที่ **รวมตัวตรวจ (YOLO) + VLM (Qwen2-VL)** สำหรับความเสียหายผิวโครงสร้าง ในวารสารสายก่อสร้างระดับสูง
- ✅ ใช้สนับสนุนว่า **VLM ทั่วไปวัดขนาดรอยร้าวจากภาพเองไม่ได้ดี** (ผู้เขียนยอมรับว่าผิด) → เหตุผลที่ T-BHI วัดพื้นที่จาก mask ของ SAM 3 ไม่ให้ Qwen ตอบตัวเลข
- ⚠ **ขัดกับแผน 3.5.3 แบบ (ก):** เราให้ Qwen เป็นตัวให้กรอบรอยร้าว แต่เปเปอร์นี้ (และทุกเปเปอร์ที่เจอมา) ใช้ detector ให้กรอบ เพราะ VLM ทั่วไปหาตำแหน่งรอยเล็กไม่แม่น — เราจึง **ยังไม่มีหลักฐานจากเอกสารว่า Qwen ให้กรอบรอยร้าวได้ แม้ fine-tune** ; ต้องเขียนเป็นสมมติฐานที่ทดสอบใน 3.8 (วัดชั้น Qwen แยก) และเตรียมเหตุผลตอบกรรมการว่าทำไมไม่ใช้ detector ตรวจความเสียหายโดยตรง
- ห้ามอ้างว่า "Qwen fine-tune แล้วดีขึ้น" จากเปเปอร์นี้ (frozen) และห้ามยกตัวเลข ROUGE เป็นความแม่นของการตรวจ
